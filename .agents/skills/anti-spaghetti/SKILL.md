# Anti-Spaghetti：架构审查与克制重构

目标是减少一次业务变更需要理解、修改和验证的范围，同时保持既有行为。不要把函数变短、文件增多、模式数量或扫描器零告警当作目标。

## 确定范围

- 阅读目标项目的 AGENTS.md、贡献规范及与本次问题有关的调用方、测试和差异。以项目现行规则确定边界，不把其他项目的目录布局或阈值复制成通用约束。
- 用户要求审查时，输出证据与方案；要求实施时，遵循已确认范围及项目的方案确认要求。已授权的小修复不重复确认，未授权的顺手重构不纳入改动。
- 保留无关脏改动。调用技能不自动授权发布、发送消息、删除数据、修改全局配置、切分支或推送。

## 先判断是否值得重构

1. 从实际变更或故障入口追踪到状态持有者、I/O 和依赖边界，定位具体问题：重复修改、隐式状态传递、依赖违规、难以独立验证，或错误恢复路径混杂。
2. 区分三类结论：已证实的缺陷或项目规则违规；需要上下文判断的结构风险；可选改善。每个重要结论给出文件位置、触发场景及影响。
3. 比较保持现状、局部简化、提取边界的成本。若抽象增加跳转、共享可变状态或间接依赖，却没有降低真实变更成本，推荐不拆分。

## 选择最小有效结构

| 已证实的需要 | 优先方案 | 不应机械套用的情形 |
| --- | --- | --- |
| 少量稳定条件分支 | 保留清晰的 if / match，必要时使用卫语句 | 分支数本身不能证明需要策略类 |
| 多种实现独立变化、共享稳定契约 | 先考虑函数映射；需要状态或生命周期时再考虑策略对象 | 不为单一实现预建注册框架或工厂 |
| 同一组数据反复一起传递且有共同约束 | 参数对象、TypedDict 或 dataclass，按边界选择校验方式 | 不仅为低于参数阈值而打包无关字段；不建立万能 Context |
| 遗留/第三方语义与领域契约不同 | 在边界适配，并明确错误和缺省值 | 不用适配器隐藏失败或丢弃必要信息 |
| 多个调用方重复相同协调流程 | 提取应用服务或门面 | 不把所有依赖塞入新 God Object，也不为减少 mock 数量掩盖耦合 |
| 巨型模块中存在可独立验证的职责 | 提取一个连贯职责，保留兼容入口并逐步迁移 | 允许在大文件里修复局部缺陷；行数不能强迫拆文件 |

- 核心依赖方向按项目规则检查；职责迁出文件后仍要检查依赖是否真正减少。
- 传递所需的最小能力或数据；避免把整个调度器/self 作为替代接口。已有稳定对象接口、简单 dict 和直接函数调用可以保留。
- 管道用于可明确描述输入、输出及失败语义的阶段。状态机、事务、重试和锁的先后顺序具有业务含义，不能为了“可插拔”任意重排。
- 只有确有独立订阅者需求且交付语义明确时才引入事件机制；同时说明顺序、幂等、失败处理及可观测性。

## 实施与验收

- 实施前列出必须保持的行为：公共接口、返回值/异常、副作用顺序、持久状态、重试及恢复语义。按实际风险选择，不生成空泛清单。
- 用现有测试或最小行为样例固定这些约束，再逐步迁移一个边界；必要时保留薄兼容入口并说明移除条件。
- 验证真实调用入口与重要失败路径；纯函数单测不能替代调度器、DAL 或状态恢复入口的证据。遵守项目隔离测试入口。
- 不通过修改测试预期、提高阈值、增加豁免或拆成碎片函数来制造通过。合理豁免应有范围、理由及复核条件。
- 说明改动前后谁持有状态、谁负责 I/O、调用方需了解哪些细节，以及增加的抽象成本。规模变化只作辅助证据。

## 可选静态扫描

扫描器只提供线索，缺失时仍可完成架构审查。先检查实际工具路径、解释器、帮助和扫描目标；不假定其他项目存在 scripts/anti_spaghetti.py、vpanel 或某个全局别名。

- 60 行函数、400 行类、16 个方法、5 个参数、4 层嵌套只能作为可调整的初筛参考。注释、声明式代码、协议实现和内聚流程可能合理超过阈值；项目未规定时不作为合并门槛。
- 只有按项目真实模块边界确认的依赖违规等确定性规则适合阻断。语法错误、读取失败、漏扫或空目标应报告检查不完整，不能作为通过证据。
- AST 语法形状不能证明高内聚、低耦合、行为等价或整个依赖图无环。报告实际扫描范围与覆盖限制，零命中表述为“在已扫描范围内未命中所实现规则”。
- 面向存量代码的告警应区分既有问题与本次新增；没有基线能力时明确说明，不能假装已做增量检查。
- Python 项目使用其受支持的解释器；Video-precessing 使用项目 .venv。检查实际退出码、成功与失败文件数及规则覆盖范围；--check 返回 0 不能证明完整架构审查通过。

## 交付

按任务需要简洁报告：结论；有证据的问题；推荐最小方案及取舍；行为验证与剩余限制。保持不改也可以是审查结论。

区分技能文本、扫描器、命令包装、安装发现与运行效果。Shell 的 craft 只在实际配置后可用；自然语言别称不等于已注册的宿主命令。不能仅凭文件复制声称所有宿主均可发现或跨项目调用正常。
