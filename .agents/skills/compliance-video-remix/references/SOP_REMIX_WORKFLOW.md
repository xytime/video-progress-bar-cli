# 合规二创操作与验收 SOP

本 SOP 以统一 CLI、PipelineDB 审批记录和不可变内容摘要为准。目标是让每个动作有来源证据和明确授权；规则通过不是平台合规保证。

## 1. 提案

使用 `--propose --url`。仅接受支持的 YouTube 链接或合法来源标识。元数据和带时间戳的字幕必须完整可用；抓取错误、缺字幕、超出受支持长度时明确失败，不以标题代替，不静默截断。提案阶段不得 TTS、渲染母带或提交。

核对返回的独立提案 ID、内容摘要、完整对照表、来源证据、工作目录和期限。待审记录不能进常规自动队列，也不能覆盖源视频任务。

## 2. 人工审查与批准

逐句核对事实和来源时码、所有封面/标题/标签/关键词/徽标/卡片文本。逐镜头确认画面可用，尤其人物、外媒文字、争议画面与叙述之间是否对应。不能将模型自己生成的 reviewed 字段当作人工证据。

通过 Telegram 的制作按钮或带准确提案上下文的 CLI `--execute` 批准一次执行。批准必须绑定当前内容和用途。取消是持久撤销；改内容、过期或已领取后，旧批准均失效。发布用途不能从仅制作批准升级。

## 3. 制作

执行重新校验快照、结构与全部输出文本，领取一次任务后才进入生产。生成音频前完成依赖和镜头前置检查；缓存按内容与参数绑定。镜头以实际时长循环覆盖口播，源音频移除。字幕输入先消除用户 ASS 控制语法，再做原子高亮和标签感知折行。

维持既有 1080×1920、Alignment 8、MarginV 570、980×240 卡片规格。标准封面使用既有 CoverEngine 及真实 provenance；不写假图像或假来源证明。

## 4. 发布与异常

发布只能经已证明复用现有准入、锁、节流、幂等和账本的适配器。整改版本如报告发布适配尚未接通，保持阻断；不得复制旧命令直接调用上传器绕过。

本地完成不等于平台受理，受理不等于公开可见。非零退出、缺失回执、旧回执、已提交未绑定 ID 等必须保留独立状态。提交意图出现后或结果未知时禁止自动重传。超时清理后代并保存失败或未知结果。

## 5. 演练与验收

`--manifest ... --dry-run` 只验证，不能改变审批、覆盖母带/封面或写生产回执。示例为明确合成素材，不具备实际发布资格。

开发验证仅通过仓库的隔离测试入口运行：核心、Telegram、DAL 竞争/撤销/过期/篡改、模型 fixture、Unicode 混淆、路径/ASS 注入、缓存、FFmpeg 实际短源、超时与回执状态回归。真实模型、真实 TTS、人工画面审阅和平台提交另行授权验证，测试通过不冒充这些证据。
