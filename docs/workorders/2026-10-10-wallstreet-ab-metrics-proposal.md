# 华尔街 A/B 指标采集方案

作者：Codex（具体模型身份未知），2026-10-10。状态：具体实施提案，尚未上线自动采集。

## 推荐执行方式

复用现有每分钟巡航，增加只读指标阶段，按各平台每件作品的公开时间采集 24、72、168 小时累计快照。每轮最多读取 4 件到期作品，共用一次后台登录上下文；上传、互动会话锁及发布优先级优先，忙时延后。失败按 5/15/60 分钟重读；失败只影响指标，永远不重传视频。

身份使用 `(pair_id, variant, platform, account, platform_post_id)`。视频号只接受原生 ID 精确匹配、原提交回执的唯一 nonce 精确匹配，或具有用户完整原生预览确认及独立精确回读的审计恢复。标题、封面、时间、排序不作为自动绑定依据。抖音使用作品原生 ID。

首选创作者后台原生只读响应，与同 ID 的后台数据显示交叉核验。视频号已观察到 `readCount / likeCount / commentCount / forwardCount / favCount / followCount`，仍需完成字段与 UI 一一对应验收；抖音对应字段及可用读取接口尚待真实验收。不支持的字段保持 null，后台导出可作为按同原生 ID 录入的替代路径，不能伪称自动读取已完成。完播率与平均观看时长要先确认单位和分母；不能猜百分数或毫秒。

## 存储与可比性

复用 `wallstreet_metric_snapshots` 的 `(publication_id,horizon_hours)` 唯一键及原生 ID 检查。保存脱敏原生字段 JSON、后台截图、采集时间、公开时间及其依据、实际作品年龄、采集状态。现有 DAL 允许较晚快照覆盖同窗口，实施时应增加“已验收快照不被更晚作品年龄覆盖”的封闭策略：原始采集证据只追加，窗口选择距目标时点最近且在容差内的一次；不要把多次累计读数相加。

平台公开日期须来自已发表 DOM 日期与同一卡片原生时间一致的证据；仅有首次观察公开时间的作品保留时间不确定标记。推荐窗口容差 ±2 小时；超过容差标记 late，仍可展示累计数，但不进入严格 A/B 比较。缺失不是零，零播放不计算比率。

## 报告

每个平台、每个账号分别比较同源 A/B 的同年龄窗口；只统计两版都公开且身份、时间、快照齐全的 PAIRED，B_ONLY 不进入配对结果。主指标为 `(点赞+评论+分享)/播放量`，同时展示播放数及每千次播放的评论、分享、收藏、关注转化，有可靠数据时再展示完播率、平均观看时长。报告 A/B 绝对值、差值与相对变化；分母为零或缺失则相对变化为空。

达到 20 组完整配对后复盘，同时记录 A 先发、B 至少晚 6 小时带来的新闻时效、发布时间和自然流量差异。这是观察性配对实验，不把自然流量变化写成随机实验的因果结论。

## 实施验收

1. 两个平台各验证一件已公开作品的原生 ID、UI 与字段读数相符；任何 ID 冲突拒绝入库。
2. 一组真实 PAIRED 取得两版同年龄的 24 小时快照，检查实际年龄与字段单位；再验收 72/168 小时调度。
3. 重启、重复巡航、会话忙、登录失效、缺字段、零播放、过期快照均不重传；保持原投稿尝试次数不变。
4. 日报明确显示完整配对数、缺失原因与下一次采集时间，自动采集启用前保持“人工导入/方案待实施”。

当前没有有效完整配对快照，不能据此判断 A/B 优劣。退休金普通版当前读数最多可另存诊断基线，不能冒充发布 24 小时结果。
