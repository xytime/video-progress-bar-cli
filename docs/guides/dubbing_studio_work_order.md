# DUB-001 已发布视频普通话配音再制中心

## 1. 背景

当前主链路负责发现、加工并发布 YouTube 视频。字幕翻译和竖版渲染已经可用，但普通话配音不应进入每天的自动发布流程：运营只会从已发布内容中挑选少量优质视频，再制作并单独发布普通话 TTS 版本。

旧配音实现按视觉字幕框逐条合成，再用强制调速防止重叠。这会切断自然句、造成连接突兀，并使中文字幕的显示时间与实际中文语音脱节。多人访谈还缺少说话人区分，无法为不同说话者稳定分配音色。

本工单建设一个独立的“配音再制中心”。它以已发布视频为输入，产出可审核、可单独发布的 TTS 版，不改写原视频、原发布记录或既有自动调度。

## 2. 目标

1. 运营可从已发布视频中显式选择一条或多条，创建普通话 TTS 再制任务。
2. 使用 MiniMax `speech-2.8-turbo` 生成自然、偏快但清晰的中文配音。
3. 通过说话人分离、音色映射和时长闭环，实现单人讲解与多人访谈的可理解配音。
4. 最终成片只含中文配音音轨，中文字幕以实际 TTS 时间轴生成。
5. TTS 版拥有独立审核、平台投递和发布确认记录；原视频发布状态永远不被改写。

## 3. 非目标与硬边界

| 不做什么 | 约束 |
| --- | --- |
| 不改变现有自动发布链路 | `PipelineManager`、定时任务、候选评分、发布窗口和原视频重试均不得自动领取配音任务。 |
| 不覆盖原始素材 | 不覆盖原 MP4、ASS、封面、文案或 `processed_videos` 状态。 |
| 不默认自动发布 | 生成成片后必须人工确认，再进入独立发布流程。 |
| 不把说话人标签当实名 | `SPEAKER_A/B` 只代表当前视频内的同一声音；跨视频身份识别必须另建声纹库和人工确认机制。 |
| 不用极端调速掩盖翻译失配 | 无法自然对齐时进入改写/人工审核，不能产出拖沓或听不清的成片。 |

## 4. 使用场景

### 4.1 单人财经讲解

运营从已发布列表选择一条英文财经演讲，确认男声主播音色，生成普通话配音版并人工检查后单独发布。

### 4.2 男女对谈或访谈

系统将声音分成 `SPEAKER_A/B`，分别推断声线属性；运营确认映射后生成交替配音，保持整支视频内角色音色一致。

### 4.3 两位同性说话者

系统仍按不同声纹分离为不同 speaker，而不是合并为“男声”。运营需选择两种可区分的同类音色；对低置信度或重叠片段进行人工确认。

## 5. 用户流程

```mermaid
flowchart LR
  A[已发布视频列表] --> B[创建 TTS 再制任务]
  B --> C[素材快照与内容审查]
  C --> D[说话人分析与配音稿]
  D --> E[运营确认音色映射]
  E --> F[MiniMax 合成与时长闭环]
  F --> G[重定时字幕、混音、渲染]
  G --> H[人工质检]
  H --> I[单独投递 TTS 版]
  I --> J[平台侧确认发布]
```

创建时运营可配置：目标平台、是否启用说话人区分、speaker 音色映射、是否保留经人声分离后的背景音乐，以及是否只生成成片而不进入发布准备。

## 6. 领域模型与状态机

### 6.1 独立数据模型

新增 `dubbing_jobs`、`dubbing_speakers`、`dubbing_utterances`、`dubbing_artifacts`、`dubbing_publications` 五类记录。`dubbing_jobs` 仅引用源视频 `(youtube_id, slice_index)`，不得复用 `processed_videos.tts_provider`。

| 对象 | 关键字段 |
| --- | --- |
| `DubbingJob` | 源视频引用、状态、配置快照、任务版本、目标平台、失败原因 |
| `DubbingSpeaker` | `speaker_key`、性别推断及置信度、人工确认值、voice ID |
| `DubbingUtterance` | 原始时间窗、原文、中文配音稿、speaker、实际时长、对齐策略 |
| `DubbingArtifact` | 配音音频、实际字幕、渲染 MP4、校验哈希、质检报告 |
| `DubbingPublication` | 平台、提交身份、审核状态、平台可见证明 |

### 6.2 状态机

`DRAFT → ANALYZING → VOICE_MAPPING_REQUIRED / SCRIPT_READY → SYNTHESIZING → ALIGNING → RENDERING → QA_REQUIRED → READY_TO_PUBLISH → PUBLISHING → UNDER_REVIEW → PUBLISHED`

失败进入 `FAILED`；文本无法自然等时则进入 `NEEDS_REWRITE`。任何异常均不得自动降级为 Edge 音色、单一错误音色或自动发布。

## 7. 架构要求

模块放置于 `src/video_processing/dubbing/`，由单一 `DubbingService` 编排；领域层不依赖 Web、CLI、脚本或平台上传器。

| 边界 | 职责 | 禁止事项 |
| --- | --- | --- |
| `SourceAssetPort` | 读取已发布视频及其字幕、文案、封面快照 | 不修改原产物 |
| `SpeakerAnalysisPort` | 说话人分离、重叠/置信度信息 | 不决定发布 |
| `ScriptAdaptationPort` | 生成等时中文播报稿并校验数字、实体、方向 | 不直接调用 FFmpeg |
| `TTSProviderPort` | MiniMax 请求、音频、字幕时间戳、用量元数据 | 不读取数据库 |
| `TimelineRendererPort` | 音频对齐、重定时字幕、最终渲染 | 不调用平台上传 |
| `DubbingRepository` | 通过 DAL 保存任务和产物元数据 | 业务层不得执行原始 SQL |
| `VariantPublisherPort` | 复用平台适配器完成独立投递和平台侧确认 | 不更新原视频发布状态 |

`PipelineManager` 不应导入 `dubbing`。Web/CLI/Telegram 仅调用 `DubbingService`，保证入口很薄、领域逻辑可独立单测。

## 8. 说话人分析与音色映射要求

1. 使用说话人分离模型输出时间连续的 `SPEAKER_A/B/...` 标签，并与 ASR 片段对齐。
2. 单独保存性别/声线推断及置信度；不得用性别推断覆盖 speaker 标签。
3. 自动映射仅在置信度满足阈值时生效；否则任务进入 `VOICE_MAPPING_REQUIRED`。
4. 默认候选：男声使用 `Chinese (Mandarin)_Male_Announcer`，女声使用 `Chinese (Mandarin)_Warm-HeartedAunt`。
5. 同性多人必须使用不同、可辨识的音色；音色选择由配置表维护，不硬编码在业务逻辑。
6. 重叠说话、背景噪声、声线相近和声源切换必须作为质检风险显示给运营。

## 9. 配音稿、时长与字幕要求

### 9.1 等时中文稿

配音单位是完整语义句或短段，不是视觉字幕框。中文稿必须保留人名、机构、金额、百分比、方向性和结论；数字在进入 TTS 前规范为可朗读形式。

当时长不匹配时，优先顺序为：

1. 调用 MiniMax 的语速参数重新合成；基准速度为 1.08。
2. 仅在小误差内做音频微调。
3. 生成受目标时长约束的中文改写候选，并重新通过实体/数字/语义校验。
4. 仍无法满足质量阈值时转 `NEEDS_REWRITE`，等待人工编辑。

短文本不得被拉成龟速；长文本不得被压成不可理解的快读。建议正常语速下限 0.96、上限 1.28，超过 12% 的残余失配禁止自动成片。

### 9.2 字幕与混音

1. MiniMax 返回的实际句/词时间戳是 TTS 版中文字幕的唯一时间轴来源。
2. 成片只映射新中文音轨，英文原声不得残留。
3. 背景音乐保留属于可选能力：必须先人声分离，再以旁白 ducking 混音；v1 默认完全替换原音轨。
4. 渲染前记录每段目标时长、实际时长、重合成次数、语速、停顿和最终误差。

## 10. 质量、安全与发布要求

- 所有中文配音稿进入与原视频同等级的内容安全检查；检查失败禁止渲染和投递。
- API Key 仅由 `settings.py` 声明并从本地 `.env` 读取；日志、报告、数据库和 Git 中不得出现密钥。
- 合成调用必须缓存文本哈希、模型、音色和参数；重跑命中缓存不得重复扣费。
- 质检页必须展示说话人映射、对齐误差、音频波形/试听、字幕预览和风险片段。
- 平台投递仅在人工确认后触发；最终 `PUBLISHED` 仍须由平台作品管理页或平台可见结果证明。

## 11. 验收标准

1. 创建、失败、删除配音任务均不改变源视频的状态、产物和既有平台账本。
2. 日常调度、评分、重试、发布窗口和历史补发不会自动领取 `dubbing_jobs`。
3. 单人视频可以生成只含中文音轨、带重定时中文字幕的独立 MP4。
4. 两位说话者的音色在整片保持一致；同性访谈可区分角色。
5. 对齐误差超阈值的片段必须阻塞，且质检页能定位原因和时间窗。
6. 重跑相同任务不重复调用已缓存的 MiniMax 合成结果。
7. TTS 版发布拥有独立审核与平台确认记录，不能把原视频的 `PUBLISHED` 当作其发布成功证明。

## 12. 分期与工单拆分

| 阶段 | 工单 | 交付物 | 不包含 |
| --- | --- | --- | --- |
| P1 | DUB-001A | 独立任务表、已发布内容选片、单人 MiniMax 合成、时长报告、单独成片 | 自动发布、多人、背景音乐 |
| P2 | DUB-001B | 说话人分离、人工音色映射、多角色配音、风险片段质检 | 跨视频身份识别 |
| P3 | DUB-001C | 等时中文改写、实际字幕重建、背景音分离与 ducking | 无人审核的极端失配放行 |
| P4 | DUB-001D | 独立平台投递、审核回查、平台侧发布证明 | 接入原视频自动发布调度 |

## 13. Definition of Done

- 通过领域层、DAL、时长策略、音色映射和渲染契约的单元测试。
- 以至少一条单人讲解、一条男女对谈和一条同性访谈完成离线成片验收。
- 所有生成结果具备可追溯的输入快照、用量、音色、时间轴、质检报告和产物哈希。
- `PipelineManager` 的默认行为、既有发布调度和原视频状态机保持不变。
