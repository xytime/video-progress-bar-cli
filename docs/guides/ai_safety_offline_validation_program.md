## 0. 持续协作协议

本文件是“内容安全与 AI 审查”事项唯一的路线图和验收来源。后续工作不另建平行计划；每次讨论、实验或代码改动都必须能对应到本文件中的一个工作项。

1. 同一时间只能有一个活动实验 ID。开始新项前，必须在第 9 节将上一项标为完成、拒绝或重复，并写明证据路径和原因。
2. 每轮开始先确认：当前活动 ID、唯一假设、生产边界、样本/请求/预算上限和本轮验收标准。缺少任一项时，只能补计划或做只读调查，不能调用第三方 API 或修改代码。
3. 每轮结束必须回写：输入版本或 hash、原始报告路径、通过与失败样本、成本和延迟、当前决定、残余风险以及唯一下一项。测试通过不等于可以晋级。
4. 下列不确定性必须先向负责人提问，不能自行假设：是否外发新的内容类别、是否提高预算或请求上限、是否改变生产默认行为、是否改变发布/人工审核状态，以及是否从 O2 晋级到 S1 或更高阶段。
5. 不影响上述边界的实现细节，采用更保守、可回滚的方案，并在实验记录中说明假设；不得因等待完美信息而让已定义的离线验证停滞。

每一个可执行实验都应在 `output/research/<实验ID>/` 保留原始 JSON 与汇总报告；可复用脚本、测试、样本 schema 和本文件的状态更新进入 Git。敏感原文、密钥和完整推理文本不进入 Git。

## 1. 不可突破的边界

1. 现有 P0/P1/P2 规则和发布前 fail-closed 闸门是生产底线；任何 AI 实验不得绕过、弱化或覆盖它们。
2. 离线实验不得写 `PipelineDB`、不得创建或修改发布任务、不得调用浏览器上传器、不得重启 `vpanel` 或调度器。
3. 离线实验默认 dry-run。涉及第三方 API 的执行必须显式传入 `--execute`，并在报告中记录样本上限、请求次数、模型、token、费用和失败原因。
4. AI 的“高风险”结论在验证完成前只产生报告；未来进入生产后也只能产生 `REVIEW_REQUIRED`，不能自动放行 P0/P1 命中，也不能自动永久拉黑内容。
5. 平台可见的 `PUBLISHED`、浏览器点击或 toast 都不是安全性证明。所有结论必须能够回溯到输入、规则/提示词版本、模型版本、输出、人工标签和平台管理端证据。

## 3. 两条独立工作线

### 3.1 翻译模型效率线（AI-TR）

目的：决定字幕翻译是否需要 thinking，以及在不降低字幕质量的前提下如何控制成本与延迟。

- 对照必须使用同一模型、同一提示词、同一字幕片段；唯一变量是被检验的参数。
- 需要交叉执行顺序，避免第二个请求因提示缓存而获得不公平的成本或延迟优势。
- 样本按财经、科技、演讲/教育至少三类分层，保留短、中、长片段；同一轮只扩大一个维度。
- 质量必须同时看：段落数与 ID 对齐、结构化解析、既有质量守门、金额/实体/术语一致性，以及双盲人工抽检。
- 费用只以 API 返回 usage 和当次价格快照计算；缓存命中、缓存未命中、折扣、税费必须分别说明，不能用“调用次数”代替成本。

当前阶段：`AI-TR-001` 已完成一次 12 段的小样本探针。它证明两种模式均能通过既有质量守门，但存在执行顺序和缓存混杂因素，**不构成关闭 thinking 的决定依据**。

### 3.2 语义安全审查线（AI-SF）

目的：弥补词表对未知风险、语境、讽刺、隐喻和跨句组合的盲区，同时避免模型把普通财经、科技或教育内容误判为敏感内容。

- 规则引擎先全量扫描；AI 只处理规则未覆盖、规则命中但需要语境解释、或人工历史判定有争议的样本。
- AI 必须返回固定结构：`risk_level`、`decision`、`confidence`、`evidence_spans`、`policy_category`、`uncertainties`。不得存储或依赖模型长推理文本。
- 离线阶段的 `decision` 仅可为 `ALLOW_CANDIDATE`、`REVIEW_REQUIRED`、`HIGH_RISK_CANDIDATE`；不改变任何视频状态。
- 生产候选阶段中，AI 不能作为 P0 的唯一依据。对规则未命中而 AI 高风险的内容，只能挂起人工审核。
- 每条样本都要有人工标签、标签来源和复核日期；“平台未处罚”不等价于“安全”。

## 4. 统一实验合同

任何 AI-TR 或 AI-SF 实验开始前，必须创建一个实验条目，包含：

| 字段 | 要求 |
| --- | --- |
| 实验 ID | 单调编号，例如 `AI-TR-002`、`AI-SF-001` |
| 假设 | 一句话说明只验证什么，不混合多个改变 |
| 输入清单 | 视频/字幕/文案的不可逆 hash、来源和样本分层；报告默认不外泄完整敏感文本 |
| 基线 | 当前生产规则、模型、提示词和参数版本 |
| 候选 | 唯一改变量及其版本 |
| 上限 | 样本数、最大字符数、最大请求数、最大预算、超时 |
| 指标 | 质量/安全/延迟/成本的预先定义指标 |
| 结果 | 原始 JSON、汇总报告、失败样本和人工复核结论 |
| 决定 | `REJECT`、`REPEAT`、`SHADOW_ELIGIBLE`，以及批准人和日期 |

实验输出只进入 `output/research/`，该目录被 Git 忽略。可复用的脚本、测试、样本 schema 和结论性 Markdown 才进入 Git。

## 5. 样本与标签标准

### 翻译样本

- 第一批：每个领域至少 3 条视频，每条 12 到 25 段；总量小于 9 条视频。
- 第二批：仅当第一批不存在质量退化信号时，扩大到每领域至少 10 条视频，并包含长上下文、金额、专有名词和口语表达。
- 人工评分使用盲评：准确性、自然度、术语、字幕可读性各 1 到 5 分；必须记录具体错误片段，不能只写“感觉更好”。

### 安全样本

样本集按以下来源分桶，且一个样本可有多个标签：

1. 已知 P0/P1/P2 与 CP 命中，以及历史平台异常/封禁关联素材。
2. 已发布且人工确认低风险的财经、科技、教育素材，用于测量误报。
3. 规则命中后被人工放行的内容，用于测量 AI 是否放大误杀。
4. 长字幕中的跨句、翻译变体、同义表达和隐喻样本，用于测量规则盲区。

所有标签必须区分：`BLOCK`、`REVIEW`、`ALLOW`、`UNRESOLVED`。`UNRESOLVED` 不得参与精确率结论，也不得作为自动放行训练依据。

## 6. 指标与晋级门槛

### 翻译 AI-TR

进入下一轮离线扩大样本的最低条件：

- 结构化解析和字幕段落 ID 对齐率为 100%。
- 候选不新增质量守门的 blocking issue。
- 盲评平均分不低于基线，且没有新的 P0/P1 事实、金额、实体或方向错误。
- 明确报告 P50/P95 延迟、输入/输出/推理 token 和单视频费用；未报告 usage 的调用不计入成本结论。

考虑生产变更的最低条件：完成跨领域复现，且人工复核的严重错误数不高于基线。成本或延迟优势本身不是充分条件。

### 安全 AI-SF

进入只读影子阶段的最低条件：

- 所有带人工 `BLOCK` 标签的 P0 样本仍由既有硬规则拦截；不得出现回归。
- 对人工 `ALLOW` 样本，`REVIEW_REQUIRED` 误报率必须按领域分别报告，不能用总体平均值掩盖某个频道的误杀。
- 每个 `HIGH_RISK_CANDIDATE` 必须有可定位的证据片段；没有证据片段的结论视为无效。
- 模型、提示词、规则包、样本版本和费用均可重放；任何一个缺失都不得晋级。

考虑受限生产接入的最低条件：完成影子报告的人工复核，且明确由负责人批准“AI 高风险仅挂起人工审核，不自动发布、不自动黑名单”。

## 7. 分阶段晋级

| 阶段 | 名称 | 允许行为 | 禁止行为 | 晋级条件 |
| --- | --- | --- | --- | --- |
| O0 | 基线冻结 | 读取历史素材和当前规则结果 | 改生产配置、写状态 | 输入和基线版本已记录 |
| O1 | 小样本离线 | 固定上限的 API A/B、写研究报告 | 任何发布或 DB 写入 | 指标和失败样本可复核 |
| O2 | 分层复现 | 跨领域、交叉顺序、人工盲评 | 根据单一模型结论改开关 | 达到对应工作线门槛 |
| S1 | 只读影子 | 对候选内容生成独立报告 | 改视频状态、影响队列或发布 | 人工批准影子设计 |
| S2 | 人工审核辅助 | 在后台展示证据与建议 | AI 自动放行或永久拒绝 | 影子误报/漏报稳定 |
| P1 | 受限生产接入 | AI 高风险挂起人工审核 | 任何 AI 覆盖 P0/P1 或自动发布 | 明确负责人批准和回滚方案 |

未经人工批准，任何实验不得越过 O2；当前项目处于 O1。

## 8. 成本与数据治理

- 每轮必须事前声明最大请求数和最大预算；达到任一上限立即停止，不自动重试扩大。
- 费用报告按模型、缓存命中/未命中、输入/输出 token 逐项列示；价格快照必须带日期和来源链接。
- 默认不保存 reasoning/chain-of-thought，不在 Telegram 或 Git diff 中输出 API key、完整敏感字幕或原始模型响应。
- 外发样本优先使用最小必要片段；完整长字幕只有在本地规则标出明确风险窗口或人工批准的离线语境实验中才发送。
