## 评审问题与建议

### F1 · P2 · 成功重试后仍显示旧故障

复现：关键词追踪 → 重新载入（本标签页阻断请求）→ 出现“服务暂不可用，请保留当前修改并重试。” → 恢复请求 → 再次重新载入。

证据：`/api/topic-candidates/state` 和 `/api/topic-candidates/videos?...` 均返回 200，页面仍保留该提示；完整刷新后才消失。`src/web/static/js/topic_candidates.js:48` 的 load 成功路径未清理读取错误。

用户影响：无法判断重试是否成功，可能反复重试或误判服务仍停机。失败时也未明确说明当前专题和候选属于旧数据。

建议：区分读取反馈与保存反馈；读取失败明确“显示上次成功数据 + 时间”，成功重试后清除该次读取错误并更新成功时间，避免误清尚需用户处理的保存错误。

### F2 · P2 · 完成记录仍使用发布率，业务口径不一致

首页“本地受理不等于公开发布”的说明正确，但下方“4. 完成记录”仍显示“发布率 100.0%”，旁边还有“最新发布”。按钮 title 已注明“不等于所有平台公开确认”，重要限制依赖悬停，窄屏使用者难以发现。

建议：将本地流程完成与平台公开确认明确命名。当前没有公开回读证据的指标使用“流程完成率 / 最近流程完成”；若后续展示公开率，必须由独立公开核实数据计算。这里指出的是口径误导，未推断截图中的 6 条实际公开与否。

### F3 · P2 · “需关注”尚未形成可执行的优先顺序

首页 474 条异常、246 条本地受理待核实均为全部时间记录，“待微信恢复 0”也占据第一行。进入异常页后，策略限制与技术故障混在同一结果集中；虽然有筛选项，使用者仍需自行判断紧急性。

建议：保留全部时间数字作为总量，另在需关注区区分“待人工处理 / 正常策略拦截 / 历史积压”，显示影响、最近发生或等待时长与下一步；零项弱化。进入列表时延续分类与时间口径。不得直接将全部历史异常算作今日待办，也不得默认重试策略限制记录。

这是对下一版产品范围的建议，当前全部时间口径与既定 v0.3 设计一致，不归为实现偏离。

### F4 · P2/P3 · 关键词关闭态与空态缺少明确下一步

搜索关闭已显式展示，但“开启手动搜索”只是灰色按钮，没有解释开放前置条件；示例专题又处于暂停状态，使用者不易区分全局关闭与专题暂停。无搜索历史却写“最近搜索：未知”；空池统一提示“可调整筛选”，对从未搜索的用户帮助有限。配额行的太平洋日期与英文 units 增加理解负担。

建议：关闭态突出“现在可管理专题”，用文字说明“生产凭据所属项目与配额核实完成后，另行确认开放”；全局关闭与专题暂停分开解释。无历史改为“尚未搜索”，从未搜索 / 筛选无结果 / 读取失败分别呈现。配额说明“按太平洋时间结算”，详情单位用中文并按需展开。无需暴露密钥或底层配置项。

## 推荐下一步：先确认一轮小范围 v0.3.1

推荐范围：F1 错误反馈生命周期、F2 指标命名、F4 关闭态与空态；F3 先补齐分类定义和数据来源，确认后实施，不扩大到整套生产列表重写。

建议验收标准：

1. 读取失败后明确旧数据与时间；成功重试后旧错误消失、时间更新。局部失败不能错误宣告全部成功，不能清掉未解决的保存错误。
2. 未经平台公开核实的数字不标注“公开发布成功率”；首页、列表、提示采用相同口径。
3. 搜索关闭时，用户能从当前页直接知道可做什么、为什么不能搜、开放还缺什么；无搜索历史不显示未知。
4. “需关注”分类的数字与落地列表一致；说明时间范围，不把策略拦截默认当技术故障，不提供未经核实的一键批量重试。
5. 桌面和 390px 下入口、校验、错误重试、关闭返回均可用；生产搜索始终 OFF，测试不产生真实搜索调用。

实施前按既有规格确认约定收敛上述范围。搜索开放继续作为独立事项：生产凭据项目归属仍须核实，不能用本次界面验收替代配额、共享调用者及真实 API 验收。
