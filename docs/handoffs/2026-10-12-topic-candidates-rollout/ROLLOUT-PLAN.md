## 2. 共享调用者和预算建议

生产维护目录 `src/`、`scripts/` 的官方 API 入口收敛在 `utils/youtube_catalog.py`。以下三个业务调用者读取同一个 `settings.youtube_data_api_key`；无密钥时旧业务可能使用 RSS/yt-dlp，本轮没有读取该值或验证其可用性。

| 调用者 | 实际触发 / 官方请求 | 估算通用消耗 | 搜索桶 |
| --- | --- | --- | --- |
| scripts/monitor_channels.py | cron 每 30 分唤醒；频道按核心 1h、演讲 3h、其他 6h；每个到期频道 channels.list + playlistItems.list + 有新 ID 时 videos.list | 21 个批准频道：核心 1、演讲 8、其他 12；完整日最多 408 units | 不使用官方 search.list；全网探索主路径已关闭 |
| scripts/rescore_refresh.py | cron 每 3 小时 :15；最多 50 个视频，批量 videos.list | 常规 cron 最多 8 units/日 | 0 |
| english_world/research.py | 后台候选研究预筛后为空时，读取 4 个授权频道目录；通常用 yt-dlp 搜索 | 目录降级每轮最多 12 units；人工/研究次数没有统一项目日上限 | 此路径不使用官方 search.list；yt-dlp 搜索不计入 Cloud search.list 桶 |
| 新候选工作台 | 本机手动，一页 25 条 search.list + 一批 videos.list；详情最多一次重试 | 通常每轮 1、重试最多 2；模块日上限 40 | 模块日上限 20；初次试运行总计最多 3 |

408 的推导为 `1×24×3 + 8×8×3 + 12×4×3`，加评分常规约 416。前提是单调度、轮询状态正确、整日按间隔执行；不包含 bootstrap（21 个频道最多再加 63）、额外人工运行、并发旧调用者与其他主机。故这是容量估算，**不是项目强制预算**。现有英语世界每日 launchd 任务不等同于必定调用此研究服务，不能据其时间表虚构官方调用次数。

建议不申请增额、不新增密钥，先确认现有凭据项目和所有者。B 试运行设候选每日搜索 3、通用 6，人工累计总计不超过 3 次，跨 PT 日也不续跑；通过后仍需明确确认才恢复 v0.2 的 20/40。原监控优先：试运行前检查全项目通用剩余至少 **1,006 units**（试运行最多 6，给旧业务保留 1,000 的观察余量）及搜索剩余至少 3。1,000 是基于七日峰值 489 的保守观察门槛，不是已经落实的项目硬预留。

候选账本只限制本模块；若其他调用者未知、余额不足或出现 quotaExceeded，停止候选搜索，保留旧频道服务。不得为了候选搜索降低旧业务限制、临时提高额度或绕过官方适配器。共享项目登记要补“主机/程序、触发频率、配置来源、调用方法、负责人”，只记项目 ID/凭据显示名称，不记密钥。
