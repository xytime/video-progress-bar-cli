# 华尔街事实炸弹双版本配对试验

作者：Codex；2026-10-08 起草，2026-10-09 修订。
状态：用户已确认视觉样片，并要求固化流程及目标频道双版本试验；用户随后明确授权完成并上线；以下为获准实现规格。上线状态另以运行心跳验证。

## 目标与范围

比较常规字幕版与完整二创编辑版的整体传播效果。频道使用稳定 ID
`UCTK_cv-y88CScoudcXnS1Ew`（已核对 `scripts/monitor_channels.py` 的核心频道常量及品牌音色文档），
不使用模糊标题匹配。本轮覆盖视频号、抖音现有账号，并遵守各自既有启用开关；不扩展其他平台或账号。

建议在正式启用时持久记录启用时刻（Asia/Shanghai）。纳入启用后首次完成正常 A 加工、
且此前没有平台提交记录的合格作品；沿用现有选题、评分与内容审查条件。
既有已发布、审核中或提交结果不明的历史作品不自动补发；单条具名要求另行复用对应账本。
首轮收集 20 组完整配对，再决定是否调整策略；20 组是复盘节点，不是统计显著性保证。

## 版本与发布

- A：现有常规字幕版，保持现行字幕、声音、封面与文案策略。
- B：采用已确认 30 秒样片的视觉规格 `insight-editorial-mobile-2`，泛化为完整原片、导读、六条洞察、片尾思辨及
  “欢迎在评论区说说你的判断。”；保留事实提示、不因普通疑点阻断发布的约定。
- 30 秒是本次视觉预览长度，正式 B 不因此裁切原片；需要将独立样片脚本提炼为维护代码，
  不能把固定新闻标题、固定 17.3 秒访谈区间或生成效果图作为通用模板。
- 字幕保留语音指读、重点词及释义；二创解读文字采用少量手写圈画，取消逐字指读。
  品牌栏、独立页脚、真实视频号码、原片上沿 1px 进度条及手机安全区沿用已确认样片。
- 这是整体产品方案比较：画面、导读和互动邀请均有变化，结果不归因于单一设计元素。
- 每个平台、账号分别形成配对。根据用户要求正常流水线之后追加二创，固定先 A 后 B；
  旧稿的顺序均衡提案不再适用。建议 B 在同平台 A 明确公开后至少 6 小时进入下一可用提交机会；
  公共发布窗口若启用则一并遵守。A 公开状态未确认时 B 等待回读，不假设提交时间就是公开时间。
  若管理页确认 A 已公开但不提供原生公开时间，以首次确认公开时刻作为保守间隔起点，
  标记为 `first_observed_public`，不得把它写成平台原生发布时间；未确认公开则继续回读。
  6 小时是试验操作参数，不宣称最优；固定顺序带来的新闻时效偏差必须记录。
- A 准备就绪即保持正常发布调度，同时持久排入 B 加工任务；B 等待或失败不延误 A。
  B 制作失败则保留 A、
  标记配对未完成，不得把 A 再发一次冒充 B。
- 已确认成功的版本不重发；提交结果不明先回读平台，不能盲目重试。
- 每版拥有独立成片/封面/文案指纹、发布状态、平台作品 ID、公开时间及证据；原片下载与转写共享。

## 程序边界

### 运行机制：程序调度，不依赖 Codex 会话

复用现有 `PipelineManager` 加工入口、`run_ready_publications.py` 成片发布执行者及
`run_publication_window.py` 巡航/回读入口。目标频道 A 就绪后通过 DAL 原子建立配对及 B 任务，
将 B 加工置于可恢复的独立任务队列，优先满足正常加工与发布，不在 A 路径同步等待 B。
加工任务由受管本地 Python 执行者领取；提交继续走既有平台上传器、会话锁和结果回读。
已有服务与定时配置在接入时核验，避免重复注册新的调度。

策划复用既有配置选择的 AGY CLI 或 Gemini 服务。2026-10-09 用户确认继续现有 AGY 的
公开字幕、标题和脚本策划与复核，生产 `WALLSTREET_AB_REMOTE_PLANNING_AUTHORIZED=true`。
未配置环境默认 false；关闭时缺本地脚本的 B 保留待授权加工状态，A 正常发布。
禁止换供应商绕过授权，已有本地审核脚本可继续执行。
配音复用豆包，词级时码用本地 Whisper，
画面用固定模板与 FFmpeg 渲染。生成器不需要打开 Codex、AGY 图形界面或人工逐条发起。
需要运行主机、素材与磁盘、有效的策划/配音凭据及平台登录状态；登录失效则任务等待恢复。

每个任务持久保存阶段、租约、尝试次数、下次可执行时间及产物指纹；重启后恢复未完成阶段。
复用项目 FFmpeg 资源锁、平台会话锁和上传互斥，禁止二创渲染抢占正常任务的完成路径。
开关只控制新配对纳入；已受理作品仍继续只读回查。停用试验不得重新发布另一版。
运行心跳记录代码版本、模板版本、规则指纹、启用时刻及队列状态，用来验证真实采用。

目前 `_get_published_video_path` 只返回一个路径，`publication_subjects.video_id`、
`wechat_publications.video_id` 为唯一值；现有日指标按 `(video_id, platform, metric_date)` 唯一。
因此不能通过重复调用现有入口实现双发。

实现需增加明确的实验配对与版本发布实体，关联原视频/切片、实验版本、平台和账号。
不伪造 YouTube ID 或 slice_index 绕过去重；保留已有 A 的记录及回读依据，不改写历史归因。
指标快照绑定具体平台作品 ID，而不是只绑定原视频 ID。旧单发任务继续使用原有默认流程。
2026-10-09 只读核查：当前审阅 worktree 为 `2871105`，实际主目录 HEAD 为 `cb7cf35`，
主目录没有 `processors/insight_editorial.py`；最新 `sample-30s-v2` 为独立候选而非生产模板。
上线必须在当前主干基础上选择性接入维护代码、通用视觉模块及版本发布实体，
禁止直接切换正在运行的主目录到旧 worktree。通过后在流水线空闲时采用并读取运行心跳验证。

建议增加实验配对、版本资产、版本提交和指标快照实体。A 链接既有正常发布记录；
B 获得独立合法发布主体，不覆盖 A，不伪造原视频身份。
版本资产唯一键包含原视频/切片和模板版本；版本提交唯一键包含配对、A/B、平台和账号。
SQL 及迁移全部封装在 `PipelineDB`，业务层只调用 DAL。指标以原生平台作品 ID 强绑定版本提交。
双发路径使用显式 A/B 资产，不通过现有 `_get_published_video_path` 的增强替换普通版。
配对后保留对应原片、ASS 和时码，直到 B 加工成功或任务终止，防止正常清理使 B 缺素材。

## 数据与复盘

按每一版在平台确认的公开时间，采集发布后 24 小时、72 小时、7 天累计快照。
记录实际采集时间和作品年龄；采集延迟过大、缺失或零播放时标记不可比较，不能补成零互动。
同一作品的多次累计快照不相加。平台数据读取尚未验收，需验证可用采集路径；
若需后台导出，沿用同一作品 ID 和采集时点录入，不声称已自动采集。
仅有首次确认公开时刻的作品记录观察年龄及时间不确定性，不能作为精确作品年龄的完整配对。

- 主指标：互动次数率 =（点赞 + 评论 + 分享）÷ 播放量；它不代表去重互动人数比例。
- 同时展示评论率、分享率、收藏率（有数据时）、完播率、平均观看时长及关注转化（有数据时）。
- 缺少主指标所需任一字段时主指标记为缺失，仍展示可用分项。
- 不跨平台合并，不用 YouTube 的播放/点赞代替发布平台数据。
- 按源视频配对展示 A/B 差值与各分项；先报告完整配对数量、曝光、缺失、异常及方向一致性。
  低曝光、未完成配对、时效性变化明显的案例单列，不仓促宣布胜负。

这是同账号自然流量配对比较，固定 A 先 B 后，受发布时间、新闻时效与两版受众重叠影响，
不能保证随机分流实验的因果解释。

## 单条二创发布

用户给视频链接、目标平台/账号并要求“制作二创后发布”时，默认只制作并发布 B，
不隐含双发。如果该视频已属于实验，则复用同一 B 记录；既有 B 已发布则返回记录。
平台/账号缺失先查现有路由；仍有歧义时询问，不能猜测外部发布目的地。
制作失败不得把普通版作为二创版发布。提示词见 `docs/guides/masterpiece-publish-prompt.md`。

## 验收任务

1. 同一合格源视频生成 A/B 两个不同成片，独立排程且正文完整；非目标频道仍单发。
2. 重复启动、进程恢复、单版失败或未知平台结果均不会重复发布或覆盖另一版记录。
3. 显式单条二创请求只发 B，且与实验内同一 B 去重。
4. 隔离测试覆盖版本身份、顺序、时间窗、失败恢复和指标归属；第一组实际平台回读绑定两个作品 ID。
5. 每个时点用真实平台读数生成可追溯对比表，缺失数据不伪造。

首轮接入同时提供按平台作品 ID 录入/导入真实读数及配对报表；自动数据采集路径尚未验收，
可用后再接入同一快照接口，不能把指标存储完成说成自动采集完成。

机制及视觉方向均已获确认：A 先 B 后至少 6 小时间隔、20 组复盘。
验收需区分候选代码、隔离测试、实际运行采用与平台公开回读。
