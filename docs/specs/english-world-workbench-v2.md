# 英语世界桌面工作台 v2（待用户确认）

日期：2026-10-25。范围：替换 `/english-world` 只读展示为可处理任务的管理工作台。此文和 Superdesign 草图用于确认，尚未改产品代码或运行状态。

## 目标与已核实问题

用户打开后能判断今天是否正常、哪条需要处理，并在当前任务中完成下一步。当前版本把任务、独立成片、定时日志合并成同一列表，顶部计数相互重叠，失败只有技术摘要，七个报告按钮缺少处理路径。

本次只读核验：账本有 12 个人工任务、81 个成片审核项；366 个定时日志中只读最近 200 个。聚合窗口含 159 条定时记录，其中存在大量 UNKNOWN；它们不能等同于真实待办。10:00 运行停在 language_review，07:49 停在 audio_qa；独立候选目录虽有失败回执和阶段记录，但旧运行回执没有工作目录身份，不能仅凭同源视频和时间认领为该次根因。这既需要展示改造，也需要未来运行补关联记录。现有 API 已支持研究、选择候选、制作确认、审核批准和暂缓；通用安全续做及人工平台结果登记需要补管理服务，不能只加前端按钮。

## 桌面结构

- 沿用全站中文系统字体、三主题和共享导航，不重做全站。删除四个巨型计数卡及常驻双栏；采用紧凑标题、今日运行摘要、全宽任务表、按需任务处理抽屉。页面自然滚动，抽屉一层滚动，底部操作固定可见。
- 顶部：英语世界、更新时间、刷新、新建任务。今日摘要分别说明最近一次运行、当前执行/等待、下一计划时间；失败或未知运行可直接打开对应运行记录和诊断。计划安装、任务启动和实际进度分别核验。
- 三个工作视图：**待我处理 / 全部任务 / 运行记录**。默认待我处理按阻塞和最近活动排序；所有未解决业务任务均保留，超过 7 天归“历史待处理”独立折叠组并注明数量，不静默丢弃。运行日志仅进入运行记录，不冒充一条待办。
- 全宽表列：标题和来源 / 当前步骤 / 阻塞或等待原因 / 最近活动 / 下一步。首屏看见多条任务和各自行操作；点击任务打开处理抽屉。默认每页 20 条，分页常驻表尾。
- 搜索支持标题、来源、任务 ID；状态、人工/自动、创建日期范围 AND 组合；显示已生效条件、当前结果数、清除全部。查询/排序/页码/选中项写入 URL；返回、刷新和抽屉关闭保留条件、位置和焦点。新筛选从第一页开始；不在结果内的选中项关闭并提示，旧 task 深链接仍能定位对应任务或运行记录。
- 本轮桌面优先，覆盖 1366×768、1440×900 和放大字号。窄屏保持可读、可返回，无横向页面溢出，不扩展手机专属工作流。

## 任务处理与真实动作

抽屉顶部回答：现在到哪一步、为何停下、下一步是什么。按阶段展示“已完成 / 正在执行 / 等待条件 / 失败 / 尚未开始”，附真实开始、结束、最后活动时间。无心跳不得称正在运行，无证据不得估算百分比。原始错误与技术 ID 默认折叠。

| 任务情况 | 用户操作 | 必须出现的结果与限制 |
|---|---|---|
| 新建研究 | 输入可选 YouTube 来源链接，或按现有研究规则寻找候选 | 返回稳定任务 ID 和研究状态；不自动制作或投稿，不新增自由选题生成规则 |
| 等待选题 | 查看候选，选定后确认开始制作 | 候选含来源、时长、简介、准入信息；先选题，再制作确认，不能误触发布 |
| 制作执行中 | 看步骤、最近活动和阶段日志 | 保留已完成步骤；无近期执行证据时标待确认并解释，不假装持续运行 |
| 制作失败 | 查看诊断；符合条件时从失败步骤继续 | 安全续做服务属于本轮新增，不能以已有阶段日志代替。服务端核验同一输入与文件身份、原预算、未提交证据、维护态及租约；服务未支持或条件不满足时明确“暂不可恢复”及原因，不清预算或跳过 QA |
| 成片待审核 | 播放成片、看字幕与质量摘要；批准投稿或暂缓 | 预览读取该任务真实 MP4；批准前确认标题、封面、平台、必需商品和质量绑定；点击只授权该成片包，服务端原子防重并返回回执 |
| 投稿等待或登录受阻 | 展示实际等待条件、登录入口或处理入口 | 冷却、会话占用、商品核验、预算和授权过期分别说明；时间下界不承诺必定执行；不重复授权或重做已完成阶段 |
| 投稿结果不明 | 核对投稿结果 | 展示本次提交动作和本地截图、原生 ID；可打开官方作品管理页供用户核验；后台不自动回查。人工登记审核中/公开/未确认须有身份匹配证据并记录审计。登记仅更新核验记录，不调用现有 confirm-not-published-retry 接口，不启动投稿。本轮不提供不明投稿的一键重投 |
| 历史受理、审核或公开 | 查看对应记录与证据 | 明确核验时间；不把受理等同公开，不因当前不可见开放一键重发 |

所有写操作需要新增并验证桌面可信授权、请求来源校验、任务状态版本校验与审计；操作者从已验证会话取得，不能信任请求体中的 requested_by。桌面批准按真实来源单独记录，不冒记 Telegram 授权。提交中禁重复点击；冲突时保留用户输入并展示最新状态。UI 只根据服务端实时返回的动作资格显示主操作；读取失败不得沿用旧的可执行权限。不得仅凭按钮禁用实施权限。

## 证据可用性

- 证据放在相应步骤旁，直接显示“通过/失败/缺失/关联未核实”、生成时间、具体问题与修改建议；能定位的问题指向段落、词语或时间码。点击后能读报告内容或核对截图，而非只有报告文件名。
- 成片预览、质量报告、阶段日志、投稿回执分别提供固定类型入口；禁止任意文件路径访问、原始环境和凭据外泄。
- 定时运行在尚无成片前也应显示来源候选、阶段和失败依据。只有明确的 run/job/candidate/review 身份或内容指纹才能关联；仅同标题、同源视频或时间接近不能拼接多个尝试。
- 新运行补持久化关联与阶段事件以解决早期失败不可见；旧记录无法证明归属时写“历史关联不足”，保留原记录，不能借其他任务报告补齐。

## 实现边界

重构管理页面及其必要的查询、动作资格、阶段关联、受控继续、人工核验和审计服务；复用既有制作/投稿状态机，不重写媒体流水线。旧状态和证据保留，新增结构采用兼容性迁移。不批量重试、不自动重发、不改变审核规则、限额或自动发布策略，不为上线验收触发真实投稿。

## 验收：按任务完成，不按按钮数量

1. 在真实账本中区分业务任务和运行记录；今日失败能定位到对应阶段与已绑定的原因；未知/历史日志不计入实际待办，过期记录不称正在执行。
2. 从新建研究到候选选择、制作确认、成片预览形成完整流程；所有动作有服务端结果、审计和明确失败反馈。生产数据只做只读核验，写入路径在隔离测试/仿真执行器中验证。
3. 安全续做保留前序产物、授权和原预算；输入变化、预算耗尽、提交不明、并发领取、维护态均阻止非法执行并解释原因。
4. 标题/来源/ID 搜索、组合筛选、分页、零结果、失败、URL 恢复均可用；切换任务不会沿用上一任务证据或动作资格。
5. 每类质量证据能读到实际结论和问题；缺失、历史、身份不一致分别可辨。成片播放器支持拖动和暂停，使用当前任务实际文件。
6. 不明投稿可完成“查看提交依据 → 打开官方管理页 → 按身份登记核验结果”，且不会自动重投；无身份匹配不能登记为公开。
7. 1366×768 首屏显示搜索、首条任务的原因和下一步；键盘可完成任务选择、报告查看和确认，关闭抽屉恢复焦点；三主题与大字号可读。
