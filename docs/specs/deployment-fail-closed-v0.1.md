## 1. 问题与当前事实

2026-10-12 部署时，恢复脚本/备份前的检查被外部浏览器会话锁拒绝，但临时编排仍调用了源码快进脚本。旧进程已退出，新进程尚未启动；之后补齐一致性备份、重新通过检查才启动及恢复。结果可用，不代表流程没有缺陷。

现有 `scripts/maintenance_control.py` 已对不安全状态返回非零；`maintenance_runtime.inspection()` 校验来源、持锁、进程、保护与搜索关闭条件。缺少的是把每个操作与前置成功结果绑定的完整部署入口，单改退出码或提醒操作者不足以消除这次事故。

另一个已观察风险是 launchd disable 不等于已加载 KeepAlive 作业退出；停止后可能重拉起，必须回读真实加载状态、进程身份和锁。

## 2. 目标与范围

运维者通过一个受维护的本机命令完成已批准版本的部署；任一步失败，后续采用、启动或恢复动作都不得被执行。退出后能明确看到服务、维护闸门和调度分别停在哪一步，以及恢复需要哪些证据。

首期仅支持本机项目既有 cron、launchd、UI/ready-worker 与现有维护闸门；对未知来源拒绝。采用前准备并验收好目标源码与生产 dirty 的整合结果，部署入口不承担临场开发或自动解决 Git 冲突。

包括：只读计划、单进程顺序执行、持久化步骤回执、原状保留、真实停止判定、备份门禁、维护启动验收、明确恢复、隔离故障注入。建议入口 `vpanel deploy plan/apply/status/recover`；命名可在实现中调整，不改变行为契约。

不包括：修改来源哈希算法、忽略未跟踪 Python 文件、强杀/删锁、自动移动其他开发文件、整库回滚、自动 stash/reset、自动解决源码漂移、改变发布资格、处理既有 bot EX_CONFIG，以及任何真实搜索或搜索开放。源码漂移仍须停下单独核实，不能成为新入口的隐含“自动修复”。

## 3. 执行契约

### 计划与并发

- `plan` 只读生成非秘密计划：部署 ID、明确项目根目录、main 基线、目标提交、预期最终源码清单/哈希、测试回执、dirty 保留方式、来源清单、备份位置和恢复原状。不得读取密钥或输出完整环境变量。
- 只接受明确支持的操作与路径，不接受计划内任意 shell 指令，不以计划文件的 `approved` 字段代替用户授权。
- `apply` 校验计划仍与生产一致；同一项目只允许一个部署执行者，使用真实进程互斥，重复命令不能竞争停机或重复采用。
- 回执原子落盘，记录开始、完成、失败和未知结果；写回执失败也停止。成功必须同时满足退出码、结果结构与实际回读，不能只看“命令运行结束”。
- 每个外部动作前重新检查相关前提；来源回执沿用既有有效期、维护版本与哈希绑定。禁止用旧 `safe=true` 支持后续步骤。

### 唯一正常顺序

| 步骤 | 执行动作及成功条件 |
|---|---|
| 1. 基线 | 核对 main、dirty/未跟踪清单、已测整合清单、原调度状态与保护；保存非秘密原状，搜索关闭事实齐备 |
| 2. 冻结与排空 | 进入维护、按原状清单冻结新触发，等待工作自然结束；完整 inspection 通过，不只看首页 active=0 |
| 3. 正常停止 | 禁止 KeepAlive 重新派发；正常卸载明确归属的 UI 服务并等待真实退出，核对独立 worker。每次停进程前重验 PID/birth/cwd/锁；超时失败，不强杀。launchctl 返回成功不等于进程已退出 |
| 4. 一致性备份 | 停止后再次完整检查；通过 DAL 执行 SQLite backup，包含 WAL，备份可读且 integrity_check=ok；备份失败或回执未落盘，源码采用调用次数必须为零 |
| 5. 采用源码 | 再次检查仍安全且基线未漂移，仅采用已测试差异；保留无关 dirty/未跟踪文件。采用后逐项核对最终清单，重新生成绑定新源码的来源证据，不复用旧哈希回执 |
| 6. 维护启动 | 完整检查通过才启动；回读新 PID/birth/cwd、各角色指纹、路由、健康、搜索 OFF 与保护，维护状态仍为 MAINTENANCE，不接纳业务新任务 |
| 7. 恢复与结束 | 再次检查后按维护版本 CAS 恢复 RUNNING，再按原状清单恢复调度，避免重复实例和集中补跑。回读维护、服务与调度后才记完成；任何恢复部分失败都记未完成 |

步骤之间的真实状态变化不能由文档顺序消除：若外部锁、未知进程、源码变化或调度变化在检查后出现，下一个动作前复检必须阻断。对不参与项目锁的外部编辑者不宣称完全原子隔离，部署窗口仍需受覆盖源码不再被修改；检测到漂移立即停下。

程序在源码采用过程中可能更新自身文件，必须绑定本次执行的实现版本与加载来源，不能在同一次部署中混用旧编排与新模块。采用前后的源码哈希是不同检查点，都需真实匹配；不得为了让部署程序通过检查而忽略任意 PID 或放宽旧 worker 来源规则。

### 失败与恢复

- 任何检查拒绝、非零退出、超时、响应损坏、回读矛盾或回执不可写，立即结束当前前进路径并返回非零。`finally` 只释放本执行者资源、记录结果，不自动启动或恢复业务。
- 冻结后失败保留维护和已冻结状态，并明确展示停机影响、最后确认步骤、未知动作及恢复命令；不得默默结束或宣称已恢复。
- `recover` 显式执行：先回读实际 Git/文件、进程/锁、DB 备份、维护版本、调度状态及保护，再提出并执行已授权恢复路径。不能直接从日志“下一步”开始，不能因动作开始记录存在就认定动作完成。
- 崩溃发生在“外部动作成功、完成回执未落盘”之间时，应标为结果未知。通过确定性后置条件核实后才允许前进；无法消歧则停下，不重复执行或猜测。
- 源码尚未采用时，可在重新通过完整检查后恢复原版本和原调度。源码已采用时，只有已测目标、备份和实际状态都确认才继续维护启动；否则保持维护，输出人工处置条件。
- 首期不自动回退 Git 或恢复数据库备份。备份是恢复保障，不是覆盖维护期间合法数据的授权；需要回退时另行形成精确差异方案。
- 只恢复本次实际改变且仍匹配预期的调度项；若有其他人同时改动 cron/plist，停止并报告冲突，不能把原快照整份覆盖回去。原来禁用的仍禁用，原来未加载的不得顺便启动。

## 4. 工程边界与首次采用

- 沿用现有维护核心与命令接口；编排归外层运维脚本，通用门禁/步骤状态进入独立小模块，核心不反向导入 scripts。避免扩张 `maintenance_runtime.py` 为部署巨型模块。
- SQL 与 SQLite 一致性备份封装在 DAL；配置仍由 settings 定义。备份和运行回执放本机私有目录，Git 只收脱敏摘要。
- 不把新入口直接写进运行中源码再尝试停旧进程：先在隔离区验收。第一次采用新入口本身仍使用现有已验维护路径，逐步核验上一动作成功，不串联临时脚本；旧进程安全停止、备份完成后才落地新源码。
- 首次采用需单列 bootstrap 回执；不能把首次安装期间的人工分步操作宣称为新入口全流程生产验收。新入口的全流程在隔离环境通过后，可对同版本执行真实受控维护循环证明正常路径，无新增业务任务。

## 5. 验收标准

统一通过 `scripts/run_isolated_tests.py`；进程、文件、锁和 SQLite 用真实临时对象。macOS 服务控制使用隔离受控替身核对命令与状态；真实 launchd/cron 影响仅在获批生产维护窗口核验，不在测试中操作用户服务。

| ID | 可观察结果 |
|---|---|
| D01 | 对每一步分别注入非零、超时、结构损坏和回读失败；后续具有副作用的动作调用次数全部为零，错误和停止步骤准确 |
| D02 | 精确复现“检查被外部锁拒绝后仍快进”的场景：HEAD、运行源码、数据库保持不变，采用/启动/恢复均未调用 |
| D03 | 备份失败、磁盘不可写、integrity_check 不通过时，源码采用零调用；成功备份含已提交 WAL 数据，可在独立临时 DB 打开 |
| D04 | KeepAlive 重拉起、PID 复用、bootout 提前返回、正常退出超时均被识别；无 SIGKILL、无删锁、无误停旁路进程 |
| D05 | 陈旧回执、维护版本变化、源码或调度中途漂移、未知来源、外部持锁均拒绝；旧哈希不能支持新源码恢复 |
| D06 | 两个真实部署进程竞争只有一个进入执行；对同一部署重复请求不会重复备份/采用/启动；回执损坏按未知拒绝 |
| D07 | 在每个副作用前后和回执写入前模拟崩溃；恢复先核实真实后置条件，不跳步、不重复执行未知动作、不自动解除维护 |
| D08 | 非重叠 dirty、重叠已测整合文件、未跟踪文件全部保留；发生整合冲突或源文件变化时停下，测试数据不复制进生产 |
| D09 | 原启用/禁用、加载/未加载、RunAtLoad/KeepAlive/calendar/interval 各组合按原意恢复，无重复实例/集中补跑；并发外部编辑不被覆盖 |
| D10 | 无故障路径严格先停机、再备份、后采用；在 MAINTENANCE 内启动，成功后才恢复；新旧执行实现与最终源码清单均可追溯 |
| D11 | 全程搜索 OFF、无真实外网搜索、无新增候选作业/预算或验收制造的生产任务；原保护不变，日志无密钥/会话内容 |
| D12 | 生产首次采用及同版本维护循环分别记录；最终首页/关键词入口可用、角色指纹一致、调度恢复、原开发工作保留。失败则明确标未完成并保留恢复现场 |

首期完成定义：隔离反例和正常路径通过、实际采用与运行回读通过、脱敏回执及提交/推送完成。仅增加脚本、测试变绿或得到一次 `safe=true` 不算完成。
