# 管理后台首页与导航改版规格 v0.3（已确认）

编制：Codex；日期：2026-10-12（北京时间）。用户于 2026-10-12 确认本规格并要求完成上线、测试后交验。授权包含隔离开发与生产采用 A；真实搜索 B 继续禁止。专题候选产品范围仍以[已确认 v0.2/v0.2.1](topic-keyword-tracking-architecture.md)为准。

## 1. 要解决的问题与已核实事实

运营者进入后台后，应能迅速回答“现在需要处理什么、任务在哪里、关键词在哪里维护”。首页负责概览与分流，各工作区负责具体操作。

2026-10-12 13:10–13:15 的当前证据：生产首页 `http://localhost:9100/` 返回 200，`/topic-candidates` 返回 404；首页没有关键词追踪链接。生产工作区仍在 main / `0419de50cfd806353256db607878bdd34a096878`。隔离分支 `codex/topic-candidate-workbench` / `ae0e921` 已含首页链接和工作台，但尚未生产采用。

因此，“找不到入口”的直接原因是运行版本尚未采用该功能。现有“热词监控”是只读线索，不能当作专题维护与候选管理。开发与隔离验收完成不等于线上入口可用。

当前首页实测有两层统计、十个标签、长视频表、频道配置、人工加视频以及运维控件。流程阶段与发现渠道放在同一排标签；首页导航和高影响操作混在页头；全量历史数字与当日漏斗争夺视觉重点。表格中重复标题、整块黄色时间信息、密集彩色状态和小按钮降低扫描效率。证据及限制见[本轮首页审查](../handoffs/2026-10-12-dashboard-ia-review/REVIEW.md)。

## 3. 导航与功能归属

五个一级入口固定，二级最多一层。桌面选题中心默认展开，关键词追踪可直接发现；进入其他页面后保持当前定位。手机打开导航后使用同一名称与顺序，不仅显示图标。

| 一级入口 | 二级内容 | 使用目的 |
| --- | --- | --- |
| 总览 | 工作总览 | 看需要关注的记录与当前任务，进入对应工作区 |
| 选题中心 | 素材待筛选、近期高互动、关键词追踪、热词线索、手动加入生产队列 | 找素材、维护专题与整理候选；人工入队明确区别于收藏 |
| 生产队列 | 待处理、制作中、待发布、待微信恢复、异常记录 | 查看与处理已有生产任务 |
| 发布记录 | 本地受理／待核实、已完成记录 | 查看投递与确认记录；不把受理等同公开发布 |
| 配置与运维 | 频道白名单、商品挂载、平台补录与对账、运行与诊断 | 管理规则与低频操作；外观偏好仍可从页头进入 |

“关键词追踪”名称保持与已确认工作台一致，辅助说明为“维护专题关键词，整理候选视频”。不命名为自动发布白名单，也不伪装成搜索已开放。“热词监控”改为“热词线索”，保留只读说明。关键词追踪和商品挂载保留现有独立路径。

一级切换属于导航，使用链接；同一工作区的状态视图才使用标签。当前入口有文字和选中态；页面有中文标题与当前位置。首页及全局导航均提供关键词追踪入口。

## 4. 首页布局与优先级

| 区域 | 内容 | 明确限制 |
| --- | --- | --- |
| 左侧固定导航 | 五个入口与选题二级入口 | 不能依赖长表格滚动才能找到模块 |
| 页头 | 工作总览、最后成功读取时间、外观偏好 | 不放强制运行、清空、删除、扫码登录等快捷动作 |
| 运行提示 | 搜索关闭／不可读取、维护状态（有可靠来源时） | 页面刷新正常不能标成流水线健康；无来源显示未核实 |
| 一行紧凑指标 | 待筛选、制作中、待发布、异常记录 | 各数量与点击后的对应列表同口径；标注全量或时间范围 |
| 主区：需关注 | 已有登录等待、异常、投递待核实入口；最多三类 | 不把历史失败总数称为今日新增问题，不杜撰严重级别 |

| 下方：生产概览 | 紧凑漏斗，默认今日，北京时间；历史窗口在这里切换 | 与全量即时状态分开命名，不重复摆放六张累计大卡片 |

## 5. 数据与状态口径

- 首页指标从相应现有列表契约读取 total，与点击后相同 tab、过滤、排序及时间范围绑定；不能将 `/api/stats.pending` 的全部 PENDING 直接标成实际待处理队列数量。
- 发布记录保留服务端原始状态和现有归属。“本地已受理”“平台审核中”“已核实公开”是不同证据；本期不新增平台回读。没有平台公开证明的记录不得改写为已公开。
- 如果现有 API 只提供合并集合，沿用准确的合并名称并显示说明；不在前端猜分组或编造待办计数。不能从页面所见“处理中为 0”推断所有执行者空闲。
- 首页“需关注”优先提供准确记录类别及查看入口；登录、异常、平台待核实互相有交叠时分列，不加总成一个不可靠的“总待办”。
- 数据读取失败显示“读取失败”与最后成功时间。保留上次值时标注“旧数据”；首次没有可信值显示“—”，不能回退成 0 或持续显示绿色 LIVE。
- 每块状态注明来源和刷新时点。页面数据更新、执行者状态、功能采用和搜索开关分别表达；未知状态显示“未核实”。不暴露 PID、文件路径或配置细节到日常首页。
- 首页只读请求，不触发入队、评分、登录、平台回查、热榜强制刷新或关键词搜索。未显示的业务面板不保留额外轮询；概览不新增密集轮询，不覆盖正在编辑的字段或选择。

## 6. 导航、恢复与高影响操作

推荐在 `/` 的现有参数上增加 `view` 作为分区状态：overview、topics、production、publications、operations；沿用已存在的 tab、筛选、page、size、search 等参数。服务器只返回页面，分区由同一导航所有者解析，避免每个页面复制一套路由规则。

旧 tab 深链接未带 view 时按归属进入对应工作区，不能刷新后静默回总览。历史标签/参数没有证据支持时先核实；不覆盖已有持久状态。候选仍是 `/topic-candidates`，商品仍是 `/product-settings`。后退、前进、刷新保持列表过滤与页码；从首页“查看异常”进入列表后，当前条件可见并可清除。

生产操作留在其所属工作区，保留原权限、门禁、参数、结果与审计。强制运行归运行与诊断；批量清空、删除、提权等仍在对应列表的明确上下文，首页不提供一步触发。迁移入口不削弱既有确认或失败保护，也不增加权限。

商品／候选页接入共享导航时，保留其已经验证的草稿、CSRF/CAS、冲突及未保存离开确认。新导航和本期新增反馈使用原生链接、按钮、dialog 与 status 语义；不增加浏览器原生 alert/confirm/prompt。运维原始审计保留明确“查看原始审计数据”标签，不包装为本期没有实现的完整审计工作台。

未采用工作台的环境：若需要展示入口，必须显示“尚未采用”说明，不能提供通往 404 的可点击链接。已经采用且搜索关闭的环境：工作台可进入，保留专题维护与本地整理能力，搜索按钮禁用且原因可见。搜索状态未知或 API 故障时不显示开放，也不自动重试搜索。

## 7. 视觉规范与可访问性

保持现有暗、亮、高对比与字号偏好；颜色唯一运行时来源仍为 `dashboard.css` 的语义变量。待确认方案不会改写已批准的 DESIGN.md；确认后把共享导航与首页布局所有者、契约和验收证据一起登记。

- 方向是克制的运营工作台：平面面板、清楚分隔、稳定布局，去除本期区域中无业务意义的发光、呼吸、漂浮、混杂 emoji 与中英双标题装饰。
- 主操作沿用 `--blue`，导航选中态沿用 `--accent`；绿表示已确认完成，黄表示需关注，红用于确实错误／危险，未知用中性文字。颜色必须配合标签。
- 沿用系统中文字体；标题约 24px、段标题 18px、主要操作与正文 16px、辅助信息最低 14px（随字号偏好缩放）；ID／精确时间使用等宽字体。字体不从新外部服务加载。
- 控件约 6px、面板约 8px 圆角，按既有 12/14/18px 节奏布局。普通记录采用分隔线，避免每条记录再套多层小卡片。
- 列表标题只呈现必要的一次；有真实中文和原文时区分标签，完全相同不重复。时间为辅助信息，普通时间不使用整块警告背景。完整标题、ID 与来源可通过详情或展开读取。
- 主要链接与动作触控目标至少 44×44px；使用可见焦点、标签、landmark 与当前页语义。数字卡的导航不能只是 onclick div。
- 1024px 以下导航转抽屉；手机打开抽屉后关键词入口无需再次展开即可找到。390px 时页面无水平溢出；确需比较的任务表仅在自己的区域横向滚动，有提示，不能裁掉操作。
- 不锁定整个页面高度。长商品／专题表单、对话框和手机键盘状态仍可滚动到末尾操作；减少动态效果偏好有效。

## 9. 实施顺序与完成定义

确认后，在现有隔离工作区先建立共享导航与明确的 URL 分区解析；再迁移原列表和配置入口，完成首页层级与状态口径；最后统一触及区域的视觉和交互，并完成 H01–H14 隔离验收。

保留旧深链接与原业务调用。不对生产目录切分支、不覆盖生产未提交修改，不因首页“零任务”跳过上线来源核查。完成交付给出静态方案对比、浏览器证据、代码提交／推送状态与剩余生产门禁。

“本期完成”指隔离实现与验收完成；生产首页真正出现入口，需要另行批准 A 并在实际运行页面回读。真实搜索继续关闭，B 前置条件仍包括生产凭据项目与共享调用者证明。
