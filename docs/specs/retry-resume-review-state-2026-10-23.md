## 已确认的问题

1. **历史审查标签被当作当前失败。** 第一条技术失败后仍保留政治审查 `censor_tag`。页面据此显示红色标签；主行、切片和放行后端都使用“错误属于审查，或者存在历史标签”的宽松条件，技术失败仍会暴露复核放行入口。重新点击此入口无法修复字幕定位错误。
2. **复用仍显示正在制作。** 管线的文案、竖版成片 checkpoint 命中分支仍分别写入 `COPYWRITING`、`TRANSCRIBING`。页面无法据此判断实际执行还是复用。
3. **转录与翻译缺少可独立恢复的完成记录。** `CaptionProcessor.process` 每次先加载模型、提音频、转录、翻译，然后才定位原字幕、生成 ASS 和渲染。末端失败时，上游分段结果仅存在于内存；生词 JSON 和质量报告不足以恢复完整带时间轴的翻译分段。
4. **审核层各自批准。** P0 批准不自动批准社会动荡题材层；题材批准还绑定阶段、平台及输入/规则指纹。这解释第二条的历史多次拦截，但第一条本次失败已明确是技术错误。

## 推荐修复范围

### 一、准确显示批准状态和当前失败

- 历史命中、人工批准、当前阻塞原因分别表达；技术失败显示“原字幕定位失败”及简短原因，保留详细日志。
- 前端主行、切片及后端使用一致的当前失败判定。只有当前存在待处理的审查阻塞，才提供复核放行；历史标签本身不能成为入口依据。
- 保留既有批准记录和适用范围。同一输入、规则及适用阶段的有效批准不因普通技术重试丢失。出现其他审查层或新增证据时明确解释，不能静默冒充同一个失败。

### 二、按阶段保存和复用

- 独立保存带时间轴的 ASR 结果、通过质量检查的完整翻译结果；原子写入，校验结构、完整性及关联输入。
- ASR 绑定源媒体内容、实际切片和语音识别配置；翻译绑定 ASR 结果、语种、翻译与质量契约。标题/版式改变不应无故使 ASR 失效。
- 原字幕定位、ASS 与成片继续使用各自依赖校验。已有 OCR 观察缓存可复用；不得把未通过分类的扫描结果当作已完成的字幕处理。
- 无效或缺失产物从最早失效步骤续跑，保留有效上游。历史任务缺少可验证快照时，允许补跑一次并说明原因。
- 页面显示“复用已有文案”“复用转录/翻译”“继续原字幕定位/渲染”，只有实际执行时才显示“生成中/转录中”。

### 三、处理真实字幕定位故障

- 检查第一条视频第 169 帧及相邻帧的画面、OCR 框/置信度与临近 ASR，确定字母 `O` 的来源。
- 只有证据支持时才实施最小识别修复，并用该反例验证不会误删真实文字或影响人脸；不以关闭不确定性检查来让任务通过。
- 若该帧确实无法自动处理，明确保留技术阻塞及所需人工处置。确认前无法承诺该片一定能够自动完成渲染。

## 验收

- 人工批准后模拟字幕定位或渲染失败：页面不再将其显示为待政治复核，也不再提供错误的复核入口。
- 第一次完成转录/翻译后使下游失败，第二次重试验证 Whisper 和翻译调用次数均为 0；从失败步骤继续。
- 改变源媒体使 ASR 及下游失效；只改目标语种使翻译及下游失效；只改标题/样式保留 ASR 与有效翻译。
- 缓存截断、指纹不符、并发写入或中途退出时，不复用半成品；说明重做原因。
- 主行、切片、前后端一致；普通重试不产生人工批准，已有批准不能串到其他视频或切片。
- 对第 169 帧给出可检查的画面依据与处理结论；保留原字幕处理质量门槛。
- 使用项目隔离测试入口验证故障恢复与页面行为；不借验收触发两条历史任务的生产复核、恢复、上传或发布。
