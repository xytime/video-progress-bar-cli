## 推荐的匹配规则

每条视频挂一件商品。规则优先级如下：

1. 当前任务有可信且明确的人工指定商品时，优先采用。本轮不提供无商品发表的自动路径。
2. 华尔街事实炸弹来源（以上述稳定频道 ID 识别）优先《股市技术分析》。
3. 其他明确分类为“财经”的视频选择《股市技术分析》；财经新闻也走此规则。
4. 其他明确分类为“资讯／时事”的新闻视频选择用户上架的维特根斯坦图书。
5. 科技、健康、教育及其他类别、分类缺失或冲突的内容，默认选择《思考快与慢》。

《思考快与慢》同时作为统一默认商品。找不到指定商品、目标已下架或不可选时，
在同一次总预算内转为选择默认商品，并记录降级原因。
本规格将用户所说的“最默认的那个商品”解释为《思考快与慢》；该商品仍须从真实清单核实。
默认商品也不可用或无法确认绑定时，停止在发表前，不发布无商品视频、不任意选择其他列表项。

维特根斯坦与一般新闻的匹配是用户的运营偏好，尚无转化率证据。
维特根斯坦不扩大为所有非财经视频的默认商品；其他内容统一采用《思考快与慢》。
不新增付费模型调用或逐片远程选品，不把“英语世界”等生产类型直接当成新闻主题。

商品以平台商品 ID 与完整名称/版本共同核对。首次尚无 ID 时，只有完整名称及版本信息
能在列表内唯一命中，才允许校准；同名多版本、截断名称或身份矛盾时不选。
不回退到列表第一项；目标缺货/下架只允许转为已核实的《思考快与慢》，不任意换书。

## 推荐的发布步骤

1. 从本次任务的可信元数据和分类文件生成选品决定，记录命中规则及目标商品身份。
2. 沿用现有上传、封面、标题、内容审查、声明、位置、合集流程。
3. 在最终提交前检查当前链接状态；按规则打开“链接 → 商品”，查找并选择唯一目标；目标不可用时转为默认商品，完成弹窗确认。
4. 回到发布表单，核对实际展示的商品身份与目标相同；勾选列表项目或按钮点击成功本身不算绑定成功。
5. 清理已知商品弹窗及遮罩，并再次核验商品、标题、声明等关键表单状态，再进入原有提交路径。
6. 继续使用既有作品原生 ID、提交账本与管理页回读；已受理、审核中或结果不明的作品不因挂载问题重传。

商品操作共用现有 `WeChatSessionLock`，不启动第二个并行登录会话。
所有控件定位须以最新实际页面证据为依据，作用域限定到对应表单字段或商品弹窗，
避免商品与合集复用的“确定／取消”等按钮相互误点。

## 不让选品卡住发布

建议每次选品只有一个初始尝试和至多一个后续尝试，总预算 30 秒，包括查找、默认商品回退、确认、回读与清理。
初始目标明确不可用时，后续尝试用于默认商品；初始目标已经是默认商品时，只允许一次同页面重试。
30 秒是推荐目标，尚非实测；现场验证如发现正常响应需更长时间，应说明并调整规格。
各个浏览器动作的超时必须受剩余总预算限制，不能叠加默认等待导致超时失效。
选品前已过预算、列表为空、目标不可选、权限不足、商品下架或找不到目标，均进入有界退出。

| 状态 | 推荐处理 |
| --- | --- |
| 功能未启用 | 保持既有运行行为；此状态属于尚未采用新功能，不作为本规格的上线验收结果 |
| 类型不明／分类或频道缺失 | 选择默认商品《思考快与慢》，不能跳过挂载 |
| 唯一目标已绑定且回读一致 | 正常提交，保留选品证据 |
| 指定商品不可用或未找到 | 确认取消初始选择后，在剩余预算内挂载默认商品；核验成功后正常提交 |
| 默认商品不可用、清单为空、无商品权限或总预算耗尽 | 停在提交前，记录原因并释放会话；不能无商品发表，也不能无限等待 |
| 已有其他链接或不同商品 | 不静默覆盖或同时挂载；取消自动选品并保留冲突证据。不能确认满足本次计划时停在提交前 |
| 弹窗无法关闭、不能确认商品已清空、身份冲突 | 停在提交前并释放会话，记录明确原因；禁止带不确定商品提交 |
| 页面跳转登录／会话失效 | 沿用既有登录恢复状态，禁止为了选品另开登录或无限等待 |
| 点击发表后结果不明／商品状态未知 | 沿用现有不确定提交状态并只读对账，不重复发表 |

此前“选品失败后不挂商品继续发布”的推荐已被用户明确否定，不再适用。
商品失败不能伪装为已挂载；恢复失败不能伪装为已清空。
普通选品失败记录在现有本次发布结果中；本轮不新增 Telegram 消息或评论发送行为。

## 实现范围与依赖边界

- 一个共享的纯规则模块负责匹配；一个共享的商品界面适配器负责选择、核验与取消。上传器只编排调用。
- 规则模块依赖可信任务上下文和配置，不依赖上传脚本、数据库连接、模型或浏览器。
- 界面适配器不负责分类或上传、不会点击“发表／保存草稿”。依赖方向保持外层调用内层。
- 商品目录及开关通过 `settings` 声明并补公开配置模板；默认关闭，验收后才按已确认范围采用。
- 主 PipelineManager 及实际使用的 Highlight／二创／配音入口传递同一上下文结构；缺少上下文时选择默认商品，不能用文件名猜频道。
- 英语世界、手写学习视频等其他内容同样采用默认商品；接入不得改写历史审核包或削弱独立审核。登录、只读回查入口不执行任何选品。
- 华尔街 A/B 试验若存在，同一对的新 A/B 使用相同选品规则并分别记录结果；挂载状态不同的配对在分析时单列。
- 不改历史投稿或审核包，不补发旧视频，不扩展抖音/快手，不新增商品管理界面、佣金统计或店铺操作。

### 目标与约束

运营调整书籍、分类对应关系和默认候选时无需修改业务代码或重启服务。继续默认要求挂商品；目标不可用时使用已配置且身份核实的默认候选，无法确认任何商品绑定时停止该条提交。配置灵活性不降低商品身份、超时、清理与防重复提交要求。

### 推荐范围：一个配置来源，三个操作入口

首期采用一个带 schema_version 的 JSON 策略文件，路径统一由 Settings 声明；业务模块不再内置可独立生效的商品目录或分类映射。首期提供维护配置、预览匹配、查询实际采用状态的本地命令，后续控制台只作为同一配置的编辑器，不形成第二份状态。迁移时将现有三件商品及映射写入配置并验证等价，不要求用户重新抄商品 ID。

1. 商品目录：稳定别名、平台商品 ID、完整名称/版本、启用状态及核实来源/时间。别名用于规则引用，名称用于展示，实际选择仍精确核对 ID 与名称；核实时间不能证明当前仍可购买。一个商品允许被多个规则引用，同一个 ID 不得登记成相互矛盾的身份。
2. 匹配规则：固定优先级为单条视频人工指定 > 来源频道规则 > 内容分类规则 > 全局默认。频道按稳定 ID 匹配，分类支持明确配置的同义词。首期采用可解释的确定性规则，不加入标题关键词猜测、模型选品、随机轮换或佣金优化。
3. 候选与回退：每条规则可指定有序候选，之后追加全局默认候选并按 ID 去重。现有初始值保持财经/华尔街→《股市趋势技术分析》、新闻资讯/时事→维特根斯坦、其他/未知→《思考快与慢》。用户后续可以明确配置默认备用商品；不自动拿列表第一件充数。

单条人工指定同样遵循全局默认回退，并记录人工目标与实际回退商品；不提供无商品发表的单条例外。

### 配置更新与失效处理

- 新配置先完整校验：商品引用有效、默认候选非空、启用候选可达、同一匹配条件无歧义、ID 身份不冲突。分类冲突的输入使用默认规则；重复/冲突的配置规则拒绝保存。
- 保存采用原子替换。无效更新拒绝激活，明确显示继续生效的旧版本及错误；首次没有合法配置时阻止提交。不会静默回退到代码内置规则或无商品发布。
- 每次新投稿在进入选品前读取一次有效配置并冻结快照；同一次选择和回退不混用新旧版本。尚未开始选品的新投稿采用最新有效版本，已受理作品不重投。
- 配置状态至少显示已保存版本、最近任务实际加载版本与时间。仅有文件写入或独立配置探针不能标记为正式发布已采用。
- 首期保持总预算 30 秒、最多两次选择；允许配置至多 60 秒、至多三次。候选链长度不得超过尝试上限，超出拒绝激活，确保配置的默认回退不会因长度悄悄失效。候选去重后只有一件时，允许在预算内重试该件。
- 缺货/下架且界面已确认清空可进入下一候选；单动作超时按统一异常类型处理，只有剩余预算足够且已确认清空才能回退。身份冲突、残留绑定及状态不明立即阻止提交。

### 预览与证据

输入一条待发视频，预览输出：输入分类/来源、命中规则、首选商品、完整回退顺序、预算与配置版本。预览不登录、不上传、不发表，也不声称验证平台库存或挂载成功。

每次实际选品回执记录冻结配置版本/摘要、命中规则、各候选尝试与失败原因、实际绑定商品及证据来源。最终提交回执关联同一作品原生 ID；表单绑定、后台商品和播放页购买入口分开验收。

### 验收与先后顺序

先修复已知实际商品 ID 回读、共享截止时间、Playwright 异常转换三个缺陷，再接入新配置，以免仅把错误行为变成可配置行为。

验收包括：原三类规则迁移等价；更换默认商品只需改配置；一条未开始选品的任务采用新版本且已有任务保持旧快照；同书被多规则引用；目标不可用时按顺序回退；无效配置拒绝激活；同名不同 ID 不误选；预算耗尽或默认均不可用时没有提交动作；正常生产回执证明配置采用。平台挂载与购买入口须另有真实回读证据，离线预览不替代平台验收。

本轮不包含商品上下架操作、多账号、多商品同时挂载、转化率统计、历史视频补挂/重发或新的配置页面。待用户确认后实施。
