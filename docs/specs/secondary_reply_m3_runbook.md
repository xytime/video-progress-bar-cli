## 2. 默认关闭配置与启停

- 两个总开关默认 **OFF**，缺一不可：`enable_wechat_secondary_reply`、`enable_wechat_secondary_reply_live_submission`（见 `.env.example`）。首评开关开启不会授予二级回复权限。
- 共享配额：`enable_wechat_secondary_reply=ON` 时首评入口也走原子预占（滚动 60 分钟 ≤10、单视频累计二级回复 ≤3、上海 08:30–23:00、最小间隔 15 秒；均为运营预算，不是平台安全额度）。
- 启用：仅在 M3 获批窗口内临时设置环境变量，不改生产默认值。
- **停用**：移除/置 false 即停止新的提交；已存在的 `SUBMIT_INTENT`/`UNCERTAIN` 任务仍可通过 `--reconcile` 只读对账（对账不发写请求）。
- 本任务未启用任何 cron/常驻 worker，也不得在 M3 中启用。

## 3. 恢复方案

| 现象 | 处置 |
| --- | --- |
| 进程在 `SUBMIT_INTENT` 后崩溃 | 不重试。只读对账：重启后 `reconcile()`；找到同作者同文回复才升 `VERIFIED`，找不到保持 `UNCERTAIN` |
| `UNCERTAIN`（响应丢失、回读未见、证据保存失败） | 同上；绝不重发。证据保存失败：修复磁盘后再对账，凭据 `source=reconcile` |
| 守卫网络前拦截（`BLOCKED_BY_GUARD`） | 防重账本保留为墓碑；人工核对原因，不自动重试 |
| 手机端并发已回复 | 提交前复核会跳过；复核后到提交间的竞态无法被本地锁排除，由事后对账发现，不自动删除回复 |
| 原评论被编辑 | 旧审批因 `SOURCE_COMMENT_CHANGED` 失效；重新生成草稿并重新审批 |
| 任务行被删除 | 防重账本（含 `INTENT`/`UNCERTAIN`/`VERIFIED`）独立保留，仍拒绝再次发送 |
| 登录失效/会话锁忙 | 提交前失败，任务记为失败；确认未创建意图后可人工重新入队 |

## 4. 单条真实试运行（M3 canary）计划 —— 待授权，当前不执行

**前置条件（须先全部满足，缺任一即停止）：**
1. 用户明确授权：真实作品 ID、目标一级评论 ID、唯一一条回复文案、执行窗口。
2. 只读样本采集（脱敏）：真实评论列表/二级回复分页字段、详情区是否携带作品 ID 标识、回复 ID 位置；据此校准适配器选择器，否则适配器保持失败关闭。
3. 作者 `finder_id` 来源：从已验证登录态只读取得并与回读节点作者字段一致。
4. 审批通道：确认使用 Telegram 则配置真实审批人（须在现有管理员白名单内）与私聊 chat；否则用本地 CLI 人工确认。
5. 文案经人工审阅（中英一致、无来源事实、无 Emoji/标签）；终审以当前政策再检。
6. 流水线空闲（避开 09:00/21:00 渲染发布），且无上传占用会话锁。

**执行步骤：**
1. `--dry-run`：确认任务、目标、文案哈希（零副作用）。
2. 打开两个开关（仅当次进程），人工批准该条审批。
3. 编排提交：终审→作者回复复核→持久意图→守卫放行唯一出站→全新会话回读→凭据。
4. 立即关闭两个开关。
5. 人工在管理端与手机端核对：回复出现在正确父评论下、作者为本账号、文案一致。

**成功判据：** 平台业务成功回执 + 全新会话回读同作者同文 + 凭据（任务/账号/尝试/作品/父评论/原生回复 ID/刷新后截图）已保存 + 人工核对一致。
**中止条件：** 守卫拦截、账号不符、页面结构与样本不符、出现 `UNCERTAIN`、任何限流/风控提示 —— 立即停止，只做只读对账，不重发，不扩大批次。
**不在范围：** 批量发送、自动巡航、递归追聊、置顶、点赞/删除/举报。
