# YouTube 关键词采集 v0.4：范围纠正与验收规格

> 状态：2026-10-13 用户已确认，隔离开发与验收完成；生产阶段未执行。编制：Codex，2026-10-13。
> 本轮授权隔离开发与验收；生产搜索保持关闭，生产采用、真实试运行及准入开放另行确认。
> 本文是新增“定时采集 → 评分筛选 → 受控准入”范围的唯一规格；原 [v0.2/v0.2.1 候选工作台规格](topic-keyword-tracking-architecture.md)及验收记录作为已交付基线保留。

## 1. 目标与纠偏

用户要的是一条与频道白名单并列的 YouTube 采集来源：运营者设置关心的事件关键词，系统定时跨频道寻找近期报道、去重、更新热度，并接入现有评分筛选流程。

此前实现的是此目标的前半段基础设施：手动关键词检索和独立候选工作台。它不是视频号分类维护，但“候选工作台已交付”不等于“关键词自动采集已完成”。原首期明确暂缓了定时搜索和主流水线准入，因此不能把剩余工作表述为只差打开搜索开关。

推荐闭环：

```text
频道白名单 ── 指定频道采集 ───────────────────────┐
                                                ↓
关键词规则 ── 定时跨频道搜索 ── 候选去重/规则检查 ── 统一评分与筛选
                              ↑                 ↓
                         定期刷新热度       达标候选受控准入
                                                ↓
                                  现有制作、审查、发布流程
```

**需要明确确认的后果**：推荐开发“达标后自动准入”的能力，而不是要求每个视频再人工搬运。生产将来开启关键词准入后，符合现有条件的视频可能自动进入制作与发布。搜索、定时采集、主流水线准入分别受开关控制；本次规格确认仅授权开发和隔离验收，不授权生产开启这三项，也不授权真实发布试验。

### 现有评分的实际含义

当前实际自动评分是播放量、点赞率的热度计算，不是 Gemini 对新闻真实性或内容质量的评分。普通视频须播放量 **>1500** 且点赞率 **>3%**，基础公式才进入 80–95 分区间；否则最高 70 分。既有自动处理线是 75 分，另外还受频道上限、既有特定频道规则及处理选择器限制。

因此刚发布的报道不能因首次低分永久丢弃。v0.4 先保留观察、刷新统计再评分，不降低原有阈值、不因关键词命中加分、不把未知频道视为白名单频道。已有精确频道 ID 的政策继续按真实身份适用；关键词本身不授予频道信用。界面称“热度评分”，不标注“可信新闻”或“AI 质量通过”。

## 3. 推荐用户流程与界面

后台采集区域设置两个并列入口：**频道白名单**、**YouTube 关键词采集**。保留 `/topic-candidates` 路由兼容已有书签，界面主按钮改为“新建采集规则”。不将内容分类、只读热词面板作为此功能入口。

1. 新建规则：填写事件名称、查询表达式、类别、语言偏好、近期范围和到期日；保存后默认暂停自动采集。
2. 页面展示执行频率、预计每日搜索请求及全局剩余额度。生产未开放时可以保存规则，但启用/立即搜索明确显示阻挡原因。
3. 将来生产门禁通过且用户确认开放后，启用具体规则；每轮按最新发布时间搜索，去重、检查规则并计算热度分。
4. 低热度视频进入“观察中”，后续刷新详情再评分；展示最近统计时间和下一次刷新计划。
5. 达标候选在准入关闭时显示“已达标，等待开放准入”；准入开放后重新核实当前状态，通过才进入现有队列。
6. 可查看“搜索记录 → 候选 → 评分依据 → 准入记录 → 主队列任务”，任何失败可定位阶段和下一步动作。

界面主要区域按“规则与运行状态 → 本轮结果/需处理事项 → 候选列表 → 历史记录”排列。候选状态包括：待补齐、观察中、未通过规则、已达标待准入、已入队、已存在、已排除、观察到期；数据缺失、预算等待、请求失败不能合并成“无结果”。

示例仅用于表达检索配置，不代表已核实某地发生事件：名称“肺鼠疫报道”，查询表达式 `肺鼠疫|pneumonic plague`。运营者可补充地点或排除词；系统不自动生成同义词或拆成多条额外请求。

## 4. 默认值、预算与取舍

| 项目 | 推荐首期值及行为 |
| --- | --- |
| 调度 | 启用规则每 4 小时到期一次；最多 3 条自动规则，最多 10 条有效规则，其余可保存但不自动运行 |
| 时间语义 | 每 4 小时是调度目标；维护、市场保护时段、预算不足会顺延。显示计划时间及实际等待原因，不承诺这些时段仍按点执行 |
| 新闻时间范围 | 新规则默认最近 24 小时，可选 72 小时、7 天；现有规则保持原值，不静默收窄历史配置 |
| 规则到期 | 默认 7 天，支持 1–30 天；到期停止搜索、热度刷新和新准入；延长后重新校验 |
| 视频时长 | 新规则默认 30 秒–30 分钟，兼顾短报道；旧规则原 3–30 分钟保持不变，明确提示可编辑 |
| 语言 | 默认英语搜索偏好，允许显式调整；偏好不是语言鉴定，未知语言不伪装为已核实 |
| 单轮覆盖 | 首期每轮最多 25 条、不自动翻页；保留官方下一页标识，有更多结果时显示“覆盖受限”，建议收窄词或另设规则 |
| 搜索预算 | 沿用本模块总上限 20 请求/配额日；自动请求最多 18，另外 2 次保留给手动操作。所有搜索、重试均计数，手动也不能突破总额 |
| 详情预算 | 沿用总上限 40 单位/配额日，搜索补齐、热度刷新、允许的重试共用；批量查询最多 50 个视频，禁止每个视频各发一次请求 |
| 观察窗口 | 自首次发现起最多 72 小时，且受规则有效期限制；目标每 4 小时刷新一次。最多 200 个待观察视频，超出显示待调度且按最久未刷新优先，不静默丢弃 |
| 准入新鲜度 | 默认发布时间不超过 72 小时、详情不早于 4 小时；超出时显示到期/待刷新，不把历史达标分直接用于准入 |
| 配额日 | 继续按 America/Los_Angeles 的配额日计算，界面说明重置时间；不采用本机自然日替代 |

取舍：本方案优先在已有 20/40 本机预算内形成闭环，不能保证分钟级快讯或覆盖全部报道。3 条规则每 4 小时一轮最多需 18 次计划搜索；维护、保护时段和实际详情需求会降低完成量。频率、规则容量或预算扩张另行评审，不能以“热门事件”为由自动突破。

官方搜索支持按发布时间排序、时间范围、查询表达式和分页；语言参数是相关性偏好。结果依赖 YouTube 检索与索引，不能视为完整报道清单。参考：[YouTube search.list](https://developers.google.com/youtube/v3/docs/search/list)。本模块预算不是整个 Cloud 项目的额度证明，实际开放前仍需核实项目配额与其他调用者，参考：[官方配额说明](https://developers.google.com/youtube/v3/determine_quota_cost)。

## 5. 调度、评分与准入契约

### 5.1 调度和恢复

- 使用单一受维护协议管理的调度执行器；Web 请求只管理配置/读取状态，不因打开首页而触发搜索，也不在每个 Web worker 各启动一个调度器。
- 调度状态持久化，以规则 ID、版本及计划时段形成执行身份；先原子领取再执行，跨进程共用锁和预算。保存后重复提交、并发轮询、重启恢复不得重复执行同一轮。
- 重启后只安排一次当前到期轮次，不批量补跑所有错过的轮次；未知请求结果记录为中断/不确定，不自动退款或盲重试。
- 请求前重新校验全局开关、规则版本/状态、维护状态、现有市场时段保护和预算。暂停、过期或全局关闭后不发新请求；已有请求有界结束，状态区分正在停止与已停止。
- 暂时性请求失败显示可重试及下次调度；认证/配额等明确阻挡不得无限重试。沿用现有受限重试规则，每次外部请求独立预占预算。
- 新调度器必须纳入运行来源指纹、维护排空、故障恢复与部署检查，不能使用独立 cron 绕过这些保护。

### 5.2 评分和观察

- 候选池首先完整记录命中来源和规则检查结果；查询命中不等于内容可靠、受众适配或可发布。
- 复用现有纯评分计算，统一应用原有频道策略；对可复用政策作最小封装，不改评分公式或主 FSM。
- 评分绑定统计值、统计时间、规则版本及评分政策版本，能说明未达标原因。播放量或点赞量缺失为“待补齐”，不冒充真实零值或强制达标。
- 热度刷新与新搜索共用详情预算，按等待时间公平分配；预算不足显示待刷新，不将旧统计当作实时数据。
- 跨关键词只维护同一视频的一份最新统计；排除决定不因重新命中被清除。收藏仍是选题意向，不等于批准或加分。

### 5.3 原子准入和发布边界

- 新来源标识及命中规则关系可追溯，但不能仅增加 `source=KEYWORD` 就开放处理：现有选择器排除 `DISCOVERY`，其他来源可能被直接处理。
- DAL 以规范化 YouTube ID 进行原子“核查存在性 + 建立来源关系 + 必要时插入主记录”。与频道采集竞争也只能有一份源任务，兼容原切片复合唯一键，不修改为错误的全局唯一结构。
- 已在主队列的视频只关联来源、展示现有任务，不重置进度、不覆盖人工分数、不重新发布；已有 DISCOVERY、历史归档、失败或其他需审核记录不自动改来源或复活，展示现有状态与处理入口。
- 准入事务前重新校验规则有效性、当前评分、统计新鲜度、候选排除、视频/频道黑名单、已有处理及发布记录、维护状态与准入开关。并发修改冲突必须拒绝或重读，不能用旧快照放行。
- 主队列来源必须保留自动评分属性，不标为手工评分来跳过自动流程；新来源不得绕过现有审查、字幕、人工审核及发布保护。
- 全局准入关闭时，不增加新的关键词主任务，且阻挡尚未开始的关键词来源自动处理。已开始处理的任务继续受既有维护/停止协议约束，不承诺关闭开关会撤销已经提交的平台操作。必须核查准备、处理、重试及其他相关选择器，防止旁路。
- 首期不新增手工强制提分、跳过审核或强制发布入口。生产真实试运行先关闭准入验证搜索与评分，再由用户确认是否允许准入及后续原流水线动作。

## 6. 兼容和明确不做

保留已有专题 ID、查询原文、收藏/排除、历史候选和审计；升级后已有规则均不自动开启定时采集。频道白名单原有流程、DISCOVERY 浏览语义、主队列手工决策和已发布历史不改变。所有配置通过 settings，SQL 封装在 DAL，遵守依赖方向和隔离测试要求。

本期不做自动判断全网热点、模型扩词、模型新闻质量评分、多平台采集、无限翻页、实时新闻推送；不重做首页整体布局，也不将关键词命中视为版权、事实或发布许可证明。

## 7. 验收标准

| 编号 | 可观察验收结果 |
| --- | --- |
| K01 使用路径 | 从首页直接进入 YouTube 关键词采集；与频道白名单并列。新建、保存、查找规则可完成，关闭状态可保存但不能搜索，阻挡原因具体 |
| K02 默认安全 | 新装和旧数据升级后搜索/调度/准入默认关闭；重启、页面访问及旧 ACTIVE 状态都不自动开放；旧收藏、排除及历史来源无损 |
| K03 定时执行 | 虚拟时间跨多个轮次验证仅启用且有效规则执行；并发 worker、重复领取、重启均不重复同一轮；漏过多轮不产生补跑风暴 |
| K04 并列来源 | 非白名单频道的关键词命中可进入候选，不能因此新增频道白名单或获得托底分；既有频道采集回归通过 |
| K05 覆盖与时效 | 查询时间边界及最新排序正确；25 条截断明确提示；新旧规则时长范围迁移符合规格，旧视频及到期观察不会悄悄准入 |
| K06 统一评分 | 同一统计及频道政策得到与现有评分流程相同结果；覆盖 1500 播放/3% 边界、75 处理线、频道上限和人工锁保护，无关键词加分 |
| K07 新报道成长 | 合成视频首次低热度进入观察；后续真实执行详情刷新逻辑、更新统计再达标，不必再次搜索或手工强制提分 |
| K08 缺失及预算 | 详情缺失显示未知；预算耗尽显示待刷新。手动/自动/重试并发也不超 20/40，自动搜索不超 18；配额日切换和夏令时边界正确 |
| K09 去重与历史 | 两条关键词及频道同时发现同一视频，最终仅一份源任务，多来源可查；排除、人工分、已发布、DISCOVERY 及切片历史不会被覆盖/复活 |
| K10 准入保护 | 达标但准入关闭时仅停留候选池；开放后经原子复核才入队。入队时并发暂停、拉黑、排除或版本变更不会漏检 |
| K11 下游边界 | 准入关闭时，准备、处理、重试等自动入口不处理待启动的关键词任务；原有普通来源不被误阻挡；不能靠 source 或手工评分标志绕过 |
| K12 维护与恢复 | 维护开始后停止新领取、在途有界排空；指纹不一致、恢复未完成时拒绝自动搜索/准入；新调度器被部署维护检查实际覆盖 |
| K13 故障提示 | 分别注入断网、认证失败、配额耗尽、详情部分失败和未知响应；页面能区分无结果/部分成功/失败/等待，并给出恢复动作，日志不含凭据 |
| K14 用户端闭环 | 隔离浏览器完成建规则→调度结果→查看评分依据→刷新达标→准入→打开主任务，提供截图和任务/来源关联证据，窄屏及键盘可操作 |
| K15 隔离证明 | 使用仓库隔离 runner，外网、生产数据库和发布平台均不可触达；测试用合成事件及受控 API 响应，不调用生产密钥，不提交真实视频 |
