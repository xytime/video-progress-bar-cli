# 首页与关键词追踪修正规格 v0.3.1（已确认）

编制：Codex；2026-10-12（北京时间）。状态：2026-10-12 用户确认完整范围：隔离开发与验收、受控上线，门禁通过后最多 3 次真实试运行，再开放 20/40 本机手动搜索。

依据：[v0.3](dashboard-home-ia-v0.3.md)、[候选 v0.2/v0.2.1](topic-keyword-tracking-architecture.md)、[本轮使用者复验](../handoffs/2026-10-12-dashboard-user-audit/REPORT.md)。本文件为增补，不重写历史批准记录；与旧稿冲突时，仅在本版获确认后按此增补执行。

## 1. 目标、现状与完成定义

用户进入首页后，应能判断数据是否可信、哪些事项应先查看；从指标进入列表后口径一致；关键词页应准确反馈读取、恢复、关闭及开放状态。

完整目标包括：规格确认 → 隔离实现与验收 → 生产采用 → 真实搜索受限试运行 → 正式开放手动搜索。只完成文档、提交或关闭状态上线均不等于整个目标完成。

当前证据：

- 生产入口已采用 v0.3；本轮 live capabilities 返回 topic_available=true、search_enabled=false。
- 实际浏览器复验发现：关键词 GET 失败后重试，state/videos 两接口已返回 200，但旧错误仍保留；完整刷新才清掉。
- 首页漏斗按父任务的 **created_at（入库时间）** 选取时间窗口，并非按发布发生日统计。
- published 分子目前是 PUBLISHED 或 SUBMITTED_BOUND；原 publishing_rate 分母为 score≥75 的父任务。终态可能包含低于 75 分或人工导入记录，不能靠改标签或截断到 100% 修复集合不一致。
- 原“异常类型”使用文本匹配，分类可能交叠；部分父任务的异常来自切片，不能只看父任务状态。
- 生产仍有七项既有 tracked 改动与其他未跟踪工作。本轮只读检查，不覆盖或收编。
- 已确认的官方 API 业务调用者为 monitor_channels、rescore_refresh、english_world/research，加新候选搜索；源码相同配置引用不能证明其他主机或同项目外部调用者不存在。

## 2. 范围与授权边界

包括三项重点：读取反馈生命周期、指标口径、需关注优先级；顺带补齐关键词关闭/空态文案及开放验收说明。

沿用现有框架、主题、导航、表单、候选账本和维护闸门。允许新增只读汇总契约、DAL 分类/聚合与列表筛选；无需新增数据库表或重写历史状态。全部 SQL 仍归 PipelineDB，分类由服务端一个所有者提供。

不增加自动搜索、定时搜索、AI 选题、候选下载加工、自动发布、批量重试、自动放行或平台自动回查。收藏仍只是选题意向。频道规则、评分阈值和旧发布资格不改变。

本版已获用户明确确认，开始隔离实施。推荐确认范围包含：隔离开发、验收、维护窗口内生产采用，以及 §7 门禁全通过后的受限试运行和正式手动开放。实际凭据证据缺失、共享调用者不明或部署不安全时，不以该确认代替事实，不放行。若用户仅批准开发，则采用/开放保持未批准。

## 3. 读取与错误提示契约

关键词页分三个反馈域：运行状态/专题、候选列表、写操作（表单或整理）。读取成功不能清除未解决的保存失败、版本冲突或未保存草稿。

| 情况 | 必须呈现的行为 |
|---|---|
| 首次读取中 | 展示正在读取；依赖状态的操作保持不可用，数字不用 0 占位 |
| 首次读取失败 | “读取失败，暂无可信数据”及本区重试；不要保留无限加载文案 |
| 有旧数据后失败 | 保留相同筛选条件下的最后成功数据，标“旧数据 · 最后成功读取…（北京时间）”；状态未核实时禁止依据旧状态开启/发起搜索 |
| 更换筛选后失败 | 不能把旧筛选结果冒充新结果；明确新条件读取失败，允许回到上一成功条件 |
| 状态成功、候选失败 | 专题/状态可显示新的成功时间；候选独立标失败，不能显示“全部恢复” |
| 候选成功、状态失败 | 候选结果可显示，但状态相关写入/搜索仍按未核实处理；提供状态重试 |
| 同一域重试成功 | 清掉该域旧读取错误，更新成功时间，aria-live 温和播报恢复；保存错误与草稿保持 |
| 乱序响应、切页、连续点击 | 只接受当前请求世代及筛选上下文；晚到失败不覆盖新的成功，晚到成功不清掉新错误 |
| 403 / 409 | 分别说明会话需重新打开或资料已更新；保留草稿，不自动重发写请求 |

读取超时沿用或明确配置有限上限，不能无限等待；重试只发 GET，不创建搜索作业、不扣预算。连续点击不生成无限并行请求；局部读取故障不改服务端专题状态。

## 4. 指标口径：用可解释的集合与公式

首页上方状态总量继续使用“当前列表 · 全部入库时间”，与列表 total 同源。下方区域改为 **按入库批次的流程概览**；时间控件写“今日入库（北京时间） / 近 24 小时入库 / …”。不是今日发布数量。

定义父任务集合 B 为所选入库窗口内记录；Q 为 B 中 score≥75；L 为 B 中状态 PUBLISHED 或 SUBMITTED_BOUND。切片不独立计入此漏斗，沿用当前父任务粒度；界面给出简短可展开口径说明。

| 展示 | 定义与点击路径 |
|---|---|
| 入库记录 | \|B\|；点击精确 B |
| 评分入围 | \|Q\|；入围率=\|Q\|/\|B\|；点击精确 Q |
| 已进入制作环节 | 沿用现有 processed 状态集合，明确是该批次的当前状态集合，并非完整历史累计事件；点击同集合 |
| 本地提交/完成记录 | \|L\|；显式说明含提交受理，未证明平台公开；点击精确 L，不落到含 IGNORED/HISTORICAL_ARCHIVED 的宽泛完成标签集合 |
| 入围记录本地提交/完成率 | \|L∩Q\|/\|Q\|，显示分子/分母；替换原“发布率” |
| 入库记录本地提交/完成占比 | \|L\|/\|B\|；替换含糊的“总转化” |

为避免同类分母错配，“制作率”如继续展示，应使用 processed∩Q / Q，明确“入围记录进入制作环节占比”；不把任意 processed / Q 当转化率。分母为 0 时显示“—（无符合口径记录）”；不显示虚假的 0%/100%，不截断异常比率掩盖问题。

原 latest_published_at 来自记录 updated_at，不能改名为“最近完成时间”冒充事件时间。显示“本地提交/完成记录最近更新”，必要时可降为详情字段；若要准确事件时间，另立数据契约，不在本期倒推或补写历史。

本期不新增“公开发布率”。列表、概览、辅助说明、tooltip 和页面可见文案共同核对；信息不能仅藏在 hover 中。保留已有 API 字段兼容性，以新增明确字段替代含糊字段供新版页面读取，不静默改变旧调用者依赖的字段语义。

## 5. 需关注：三组明确动作，观察项单列

标题使用“建议先查看”，辅助说明“按事项类型排序，非严重度评级；当前记录覆盖全部入库时间”。主区最多三组，非零优先显示；全部为零时显示“当前没有这些待核实或受阻事项”，不能称全系统健康。

| 顺序 | 类别与准确范围 | 下一步文案 |
|---|---|---|
| 1 | 投递结果待核实：review 中 UNCERTAIN、SUBMITTED_UNBOUND、SUBMITTED_BOUND 父记录 | “核实投递结果”；说明未确认前勿重复提交；UNDER_REVIEW 单列观察，不混成技术故障 |
| 2 | 登录/恢复受阻：WECHAT_DEFERRED、LOGIN_REQUIRED 及异常家庭中的可靠登录匹配记录 | “查看阻塞原因”；不能将登录、资源、策略问题统称重新登录，也不直接执行恢复 |
| 3 | 执行异常待排查：当前 error 集合扣除已归入第 2 类及可确认的纯策略拦截 | “查看错误详情”；未知原因写“原因待判断”，不承诺可重试 |

辅助区域显示“观察与历史”：平台审核中、内容规则拦截，以及全部异常入口。零项弱化。策略拦截说明为“规则已阻止，按需复核”；不得一律称正常或自动可放行。全部历史记录仍可达，不删除、不隐藏到无法找回。

### 分类与时间限制

- 同一父任务在三组主事项内最多计一次，按表中顺序归属；只做展示优先级，不改变数据库状态。摘要与落地列表复用同一谓词。
- 分段父任务检查所有当前失败/登录切片。只有相关异常均有明确策略依据、且无未知/技术/登录故障时，才归“纯策略拦截”；混合情况保留在需排查或受阻组。正常兄弟切片的旧文案不能把技术故障判成纯策略问题。
- 明确策略依据采用现有 channel_policy、censorship_p0 规则；非空 censor_tag 不是充分证据，COPYWRITING/quality gate 等不能一概当内容规则。遗留文本匹配标明“根据现有错误记录分类”。
- 每组显示数量、下一步、最近记录更新时间；不可将 updated_at 当进入该状态的时间，不展示“等待超过 N 小时”或 SLA 超时。无有效时间显示“未记录”。
- 落地页携带 attention_kind 和全部入库时间，默认更新时间倒序、ID 稳定次序；显示可清除的分类标签，刷新/前进/后退保留。点击数与总量同契约；若期间数据变动，说明已刷新，不伪造静态一致性。
- 采用只读 DAL 汇总，在同一读快照完成各组统计和时间；不通过抓取首页 20 行估计全库分布，不在前端用模糊文本重复分类，不新增密集轮询。
- 标准桌面首屏保留关键词入口、建议先查看首项和当前任务标题；窄屏优先呈现入口、关注事项、当前任务，总量与辅助统计不得把任务无限向下推。

## 6. 关键词关闭态及空态

关闭态主说明：“生产搜索尚未开放；现在可维护专题，整理已有候选。”补充“开放前需核实生产凭据所属项目、共享配额并完成试运行”，不显示密钥或假定某项目已经核实。

分别呈现：全局未开放、手动模式 OFF、专题暂停/到期、维护、保护窗口、预算不足；以实际门禁返回为准，原因未知就写未核实。禁用按钮旁给原因，不依赖 tooltip。

从未搜索显示“尚未搜索”；候选空池区分尚无结果、当前筛选无匹配和读取失败。配额说明“按太平洋时间结算”，单位使用中文。恢复不会自动搜索；无自动补跑。

## 7. 从上线到正式开放的门禁和路径

### A：隔离验收及关闭状态采用

先在现有隔离工作区实现并验证；采用前重新取生产 main、dirty 和实际执行来源，以最终整合源码绑定测试。保留所有无关工作与业务数据。维护沿用 v0.2.1 的冻结新领取、自然排空、身份/锁/租约核验、正常退出、一致性备份、维护启动、原调度恢复，不依据首页 active=0 判断空闲，不强杀或删除锁。

采用后验证新指标、关注路径、错误恢复、旧业务导航；搜索仍 OFF。维护执行条件在动作前重核，不复用旧 PID 或旧快照。生产采用证据与代码/推送分别登记。

### B：真实搜索前必须补齐的证据

| 门禁 | 所需证据 | 当前状态 |
|---|---|---|
| 凭据归属 | 生产配置所有者的非秘密证明：实际项目 ID、凭据显示名称或资源 ID、配置来源与核实日期；控制台仅选中项目不能证明绑定 | 未闭环；不得读取/记录密钥本体 |
| 项目配额 | 同一实际项目 API 启用、两桶上限与最新当日用量、时间/时区；启用前刷新 | 10 月 12 日 14:33 北京时间刷新 anti-gravity：通用 510/10,000、搜索 0/100；生产凭据归属仍未知，仅作所选项目证据 |
| 共享调用者 | 本机及其他主机/程序、触发频率、调用方法、责任方、预计消耗；同项目未知调用者须先澄清 | 本机四个调用路径已识别，外部共享未确认 |
| 宿主保护 | 运行中保护启用且当前准许；维护 RUNNING、状态服务可用；未知拒绝 | 动作前实时核验 |
| 版本与恢复 | A 验收、来源绑定、OFF 停止及恢复回执完整 | v0.3.1 尚未实施 |
| 操作授权 | 用户明确确认本规格的采用、试运行与正式开放范围 | 2026-10-12 已确认完整范围 |

官方当前文档将 search.list 放在独立 Search Queries 桶，默认 100 次/日，其余通用端点合计默认 10,000 units/日；这些默认值不能替代实际项目控制台。参考 [官方概览](https://developers.google.com/youtube/v3/getting-started) 与 [search.list](https://developers.google.com/youtube/v3/docs/search/list)，2026-10-12 核对。

沿用既定试运行上限：每日 3 次搜索/6 详情单位，**整个试运行累计最多 3 次搜索，跨日不重置这个总上限**；最多 3 个专题，建议复用已暂停的“AI产业与算力”并明确恢复。并发 1、15 分钟冷却、一页最多 25 条；搜索不自动重试，详情最多一次重试。

开始时项目搜索余量至少 3、通用余量至少 1,006；另核实旧业务用量趋势及其他消费者。1,000 为观察余量而非硬预留；如果新共享用量证据要求更大保留，应先调整方案。不能增加密钥或项目绕过配额。

### C：受限真实试运行与正式开放

1. B 齐备后受控设置已核实项目与两项搜索门禁，回读实际运行生效；不得只改磁盘就声称开放。
2. 本机手动发起已有专题搜索，核对官方返回身份、时间/字段、候选入账、重复与规则标记、预算和审计。不是访问官方搜索网页或执行 yt-dlp 来冒充 Data API 验收。
3. 在真实候选上验证收藏/排除持久化，操作不进入生产队列。没有结果可用时承认未完成该生产用例，在剩余总额度内调整已审主题；不得伪造候选或突破 3 次上限。
4. 做一次 OFF 停止并等待在途终止/落账，重载确认不自动补搜索；不对正在写入的事务强杀。失败、quotaExceeded、归属/保护未知或旧业务受影响即保持 OFF，定位原因。
5. 项目用量可能延迟；保存候选请求/账本及共享调用窗口，等 Cloud 回读一致且旧业务无新增回归。无法归因的增量不当作证明。
6. 若用户已确认本规格包含正式开放，且以上全通过，则受控将日上限恢复至已确认 **20 次搜索 / 40 详情单位**，重新核验有效配置与门禁，最终保持 **DISCOVERY_ONLY**、本机手动可搜索；不自动发起第 4 次请求作证明。正式开放前项目余量至少覆盖当日候选剩余额度及旧业务观察余量。
7. 如只获试运行授权，则试运行后保持 OFF，提交正式开放决策；不以旧“最终要打开”的目标代替具体范围确认。

最终完成证据：生产采用源码/版本、真实浏览器任务、非秘密有效配置、门禁/预算/作业回读、Cloud 配额回读、旧管线正常恢复、最终 DISCOVERY_ONLY 且搜索可用。仅 capabilities.search_enabled=true 不能证明全部门禁允许。

## 9. 已确认的执行方案

确认本版三项修正及相关关闭/空态完善；批准隔离开发、验收和受控生产采用；在凭据/共享配额等证据全部齐备后，按最多 3 次试运行及验收通过后的 20/40 手动开放执行。
