# 运行配置中心：契约、覆盖与三天验收

2026-10-24。继承本次用户确认的六类独立滚动额度。当前功能位于 `/runtime-configuration`；实现完成、部署完成和真实业务验收分别记录，不相互替代。

## 唯一来源与范围

配置版本存于 `output/runtime_configuration/`：`active.json` 原子指向不可变 `versions/v-…/`，其中有 `wechat_operations`、`task_scheduling`、`observability`、`runtime_settings`、`interaction_controls` 五个领域文件及摘要清单。目录是非秘密运行配置，不随代码部署覆盖。`.env` 仅承担启用配置中心的启动项、连接、身份和凭据；秘密值不返回浏览器。

批准边界由服务端 `config/wechat_operations_schema.py` 和只读迁移基线维护。客户端不能修改边界、伪造审批或添加旁路字段。超过批准额度、缩短批准间隔、增加既有请求批量/重试等预览被拒绝应用；需要单独明确批准和受控更新。没有普通的“忽略审批”按钮。

共40项集中控制：原17项额度/重试、4项任务等待/年龄/队列登记、1项等待通知静默、17项已建立消费者适配的数值，以及1项观众回复业务总开关。其余设置不是隐形遗漏：目录自动发现全部 Settings 声明、顶层配置JSON、18组候选；每项说明来源、默认或声明值、单位、适用边界和只读原因。220项静态候选仅表示代码声明；不冒充实际执行值。

复杂配置保留领域所有者：商品与商品库、片尾、采集规则/预筛选使用已有专用编辑器和领域CAS/审计，不通过原始JSON通用编辑。文章身份、音色模板、安全规则、协议与全机锁只读，需专门审阅。配置目录不等于所有字段已开放热改。

## 运行与权限契约

- 本机真实回环对端、严格Host/Origin、持久本机会话、CSRF；不信任转发头，不扩展到远程编辑。超批准范围没有普通HTTP批准通道。
- 编辑→填写原因→服务端差异和当前用量/调整后门禁预览→确认→CAS/幂等版本提交。120秒预览到期、版本冲突或错误保留草稿。回滚载入预览并产生新版本。
- 配置写锁只覆盖短提交。计费在账号锁内持策略共享读锁，保证检查和登记使用同一版本；配置提交从不等待整段浏览器上传锁。
- 下一准入立即读取活动版本；在线后台/发布执行者/运行中的回复CLI按5秒确认。新版本触发未提交本地等待重算；不领取、不启动外部工作，不复活终态。离线定时任务显示最近采用和下次待加载，不能假报在线。
- 在途浏览器记录 `active_attempt_revision`，普通参数继续原快照；停止新回复领取的业务开关始终读取最新值。在途不中断，发送前身份/内容/提交保护继续有效。
- 回滚参数不回滚会话历史、quota_epoch、失败次数、提交意图、通知回执或UNKNOWN。缺失/坏hash/非法配置闭锁新增执行；现场损坏保留，走受控文件修复，不提供盲目覆盖。
- 正常等待采用结构化 `until`；未知期限才用300秒兜底。相同任务/原因/释放时间的等待通知按静默时间去重；成功和真正故障通知不因此被抑制。
- 旧账号调度保存与解冻入口在配置中心启用后拒绝修改；旧回复设置保存不能覆盖活动域或改变未批准时段。观众回复开关不扩大既有05:30–21:00时段、审批或内容范围。

## 真实执行者差异：必须保留的教训

Web/普通命令环境的回复开关默认False，但实际每30分钟的cron显式设置两个开关True，并提供账号及作者身份。因此一次普通进程读到False不代表系统全链关闭。迁移必须保留真实定时执行者已有开启状态，同时使后续开关由活动版本统一覆盖cron和Web；不得把迁移当成新的全天发送授权。加载证据同时包括PID、角色、配置版本、在途版本、时间与本执行者身份是否已配置，不返回身份值。

三天每6小时由父任务安排的既有12次检查复用本任务，不重复创建工程任务或平台轮询。每次先读本地有效配置、实际执行者、原生用量/回执；记录：各操作开始/成功/失败/本地拒绝数量，小时/24h用量与释放，最早下界到实际领取的延迟，队列新增/完成/净增长，技术重试链及UNKNOWN数量，重复等待通知比例，评论采集新鲜度/覆盖、普通已采集留言的已回/待回/人工/排除原因。

分两栏判断：遵循性缺陷可在既有授权内修复并验证；参数合理性问题（过紧、吞吐不足、长期饥饿、库存增长）只报告影响和建议，不自行增额、缩短间隔或扩大时段。未采集不能记作0留言；受理不等于公开；待批准商品诊断与远程push独立保留。
