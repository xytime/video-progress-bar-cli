# 合规二创审计整改执行计划

日期：2026-10-25。负责人：Codex 父代理（具体模型未核实）；开发：GPT-6.1 Sol 子代理。依据：用户要求制定完整计划后交给 Sol 6.1 开发，以及原始六项工程约束。范围从只读审查转为本计划内整改；不扩展产品功能。

## 明确目标与完成定义

将已发现的合规二创实现修复为可审计的两阶段系统：提案不能进入生产或自动发布队列；只有绑定不可变内容的有效人工批准可领取一次执行；所有生产输入先通过结构与内容校验；发布状态只依据真实回执；失败与超时不会留下可重复提交的歧义。

完成需同时交付：限定范围代码、针对审计复现的回归测试、独立复核结论、隔离测试证据、逐项闭环表和剩余限制。测试通过不代表实际模型可用、平台审核通过或公开可见。规则检测不能证明“100% 语义安全”；源证据不足、画面未审核或沙箱能力未证明时必须明确阻断对应动作。

## 授权与隔离

- 独立工作区开发，复制当前相关代码作为审计基线；保留主工作区所有无关改动，不切换主工作区分支。
- 仅使用项目虚拟环境和隔离测试入口。禁止真实模型调用、TTS、外部提交、生产数据库初始化、服务重启、密钥读取。
- 主代理复核后才整合本任务差异；若共享文件发生并发改动，逐段整合，禁止覆盖。提交只纳入本任务范围，运行采用状态单独报告。
- 不修改巨型上传器既有发布治理，不改变其他来源任务的调度行为，不新增通用插件框架。

## 依赖与职责

```text
Telegram / scripts/compliance_remix.py
  ├─ 外层 CoverEngine / 现有上传器适配器
  └─ compliance_remix 服务、契约、生产流水线
       ├─ PipelineDB（提案快照、状态、领取与发布证据）
       ├─ 已有 censor_engine / 结构化模型适配器
       └─ 字幕 / 卡片 / 音频 / FFmpeg
```

核心不读取技能目录，不导入或自行定位外层 scripts；需要外层能力时由入口注入。SQL 留在 PipelineDB 方法或其现有风格的 DAL mixin 中；环境变量仅由 settings 读取。

## 批次 A：提案、审批和生命周期（首要阻断项）

1. 以独立提案/任务身份关联源视频，避免覆盖既有原片行。一次事务创建 `source=COMPLIANCE_REMIX`、待审状态与快照；普通自动队列显式排除此来源，不采用“先 PENDING 后更新”窗口。
2. 保存规范化 manifest、哈希、源证据、工作目录和版本。审批绑定提案、内容版本、操作者/聊天上下文、用途、有效期；事务领取至多一次。撤销持久化，过期/篡改/重放/并发领取拒绝。
3. Telegram 保留管理员鉴权，校验回调格式和对象绑定；批准仅生产，发布须明确授权。CLI `--execute` 是明确人工批准入口，不能通过旧 manifest 参数直接生产；旧 manifest 仅允许无副作用演练。
4. 阶段一只获取元数据和有时间证据的字幕，不下载母片、不调用媒体生产。缺字幕、截断或无来源证据不得假造有效提案。下载源片延后执行且有超时。
5. dry-run 只验证并返回计划，不领取审批，不修改生产状态或覆盖任何成片/封面/回执。自定义工作目录通过持久记录解析。
6. 子进程超时或取消清理整个进程组并回收；如已产生提交意图/回执则保留未知或已提交停止态，禁止自动重试。

验收：真实临时 PipelineDB 证明提案不进普通队列、原片不被覆盖；取消/过期/修改后批准均失败；并发与重复批准只有一次执行；未批准 TTS/渲染/上传调用数为零；dry-run 前后文件和 DB 一致；超时无存活子进程。

## 批次 B：生成契约、内容校验与输入安全

1. 统一主机端 JSON Schema 和语义校验，两供应商返回都必须通过。必填元数据、非空章节、唯一正整数索引、有限正数时长、完整 clauses 与口播一致、有效 raw_shots、对照表及所有输出路径均受约束。
2. 修复 AGY settings 属性和 Codex 调用签名；受限环境、超时与故障记录可核验。不因提示词宣称“无工具”；无法证明 AGY 禁工具隔离时停用该通道并明确降级至已有受限 Codex，不伪造双通道成功。
3. NFKC 后处理 Unicode 控制/格式/变体选择符与分隔混淆；中文连写和英文检测并行。对封面、标签、徽标、关键词、正文、卡片等所有实际输出字符串检查；空对象、类型错误、检测异常一律拒绝。
4. 原始对照材料与最终输出分开：保留源证据供人工审阅，禁止把未审核源文直接带入成片。批准绑定事实和拟用镜头审核，未审核镜头不能进生产。
5. ID 与文件名使用安全语法且路径必须在工作目录内；字幕输入中 ASS 控制语法不能执行，标题不能注入头部；保留区间原子高亮和 tag-aware 折行。

验收：已复现的 U+2062、NUL、变体选择符、感叹号分隔、英文违规样例被挡；缺字段/非有限时长/越界路径/口播不一致在 TTS 前被挡；两供应商成功与失败 fixture 均走同一主机校验；ASS 注入不生效。

## 批次 C：媒体与发布证据

1. 以文本、音色、速度、源文件及剪辑参数内容指纹隔离缓存；非空文件不视为有效产物，探测并核验实际媒体。输出临时生成成功后原子替换。
2. FFmpeg 按精确滤镜列表验证 ass，显式路径同样验证；系统无支持则尝试 imageio_ffmpeg，均无支持则在生产前报告依赖缺失。
3. B-Roll 使用实际提取时长累计，短源、尾段截短、零/负/NaN 时长都受控；有界循环保证画面至少覆盖完整口播，避免 -shortest 丢语音。
4. CoverEngine 和现有上传器由外层适配。修正实际参数、封面口播类型与短标题契约。生产结束前全量复检。
5. 读取本次结构化提交回执，区分制作完成、未提交、已受理、审核中、未知和公开确认；非零退出、缺失/旧回执不产生 PUBLISHED。复用现有锁、提交意图、节流与去重；不自动重传不确定任务。

验收：旧缓存不会被不同文本/源片复用；真实本地小样本证明短源循环覆盖音频；所有 FFmpeg 候选缺 ass 提前失败；上传失败/无回执/已受理/未知退出分别有正确状态；本地 rc=0 永不独自证明公开发布。

## 分工与共享接口

- Sol A：DAL、remix_service、Telegram/formatter、CLI、进程生命周期测试；持有提案和审批状态。不能改 B/C 所有文件。
- Sol B：manifest_contract（新增小型契约模块）、commentary_generator、censor_guard、card_generator、subtitle_generator、对应独立测试。提供 `validate_manifest(manifest)`（无效抛 ValueError）及 `validate_identifier(value)`；生成方先完成模型字段契约，服务元数据作为可信扩展处理。
- Sol C：remix_pipeline、audio_mixer、video_compositor、外层适配器、对应独立测试。流水线保留 execute_full_pipeline API，由服务在批准后调用；构造时注入外层适配能力，缺失时拒绝实际封面/发布。dry-run 不产生文件。
- 父代理：协调接口、整合测试 fixture 与技能文档、独立安全复核、回归测试、交付闭环表。共享文件修改需先协调。

各子代理不得提交、推送、重启或派生代理。先汇报具体接口方案，再实施所属文件；不以删除安全断言或无条件 mock 成功来消除失败。

## 验收顺序与交付清单

1. 保存相关基线；各批次在独立工作区开发。
2. 子代理分别执行针对性隔离测试，汇报修改文件、行为变化、证据与未覆盖项。
3. 父代理检查真实入口、审批事务竞争、发布停止态、路径与沙箱边界，再运行核心与 Telegram 组合套件及相关 DAL/媒体回归。
4. 更新 sample manifest、技能 SOP、CLI 帮助及闭环报告，移除未经证实的绝对合规/发布成功措辞。
5. 验证主工作区漂移，整合限定差异，再做最终隔离验收。交付测试结果、证据路径、Git 状态和运行采用限制。

最终关闭条件：所有已确认缺陷均有修复与回归证据，或以明确 fail-closed 状态封住未能验证的外部能力；没有未说明的阻断项。实际模型联调、真实音色/视频视觉审阅、平台提审与运行服务加载属于后续明确授权的验收，不冒充已完成。
