## 整改要求

### 数据与执行状态

- SQL 收敛在 PipelineDB；非空旧表迁移可重复执行，保留原数据、索引和外键。
- 原子领取使用 token/lease；首次生成内容稳定存储，重试不换文案。
- 点击前持久化提交意图。提交后崩溃或确认不足进入 UNCERTAIN，只允许回读，不允许自动重发。
- 成功及已存在状态不可覆盖；按 next_attempt_at 做有界退避，最多五次；明确指定目标不跳到其他作品。
- dry-run 允许默认关闭时执行本地规则预览，不调用 AGY、不初始化迁移、不写策略、不启动真实浏览器。只读连接使用 immutable 模式；非空 WAL 的活动库拒绝预览，需使用已检查点化的独立副本，程序不会自行 checkpoint。
- 默认关闭时不派发 live 任务；`--reconcile-pending` 仅领取不确定任务回读，不发现新评论。
- 持久文案重试前再次经过当前内容安全审查；旧兼容接口不得代调用者获取 lease token。

### 浏览器与资源隔离

- 页面当前作品 ID 必须精确绑定，不以标题、数组位置或文本前缀代替。
- 只采信本次提交对应的精确请求目标、完整文本与响应；同一作者评论节点完整回读才能成功。
- 旧回调、列表响应、无关评论及局部文本不能构成成功证据；证据文件按尝试隔离。
- 评论、上传及保活使用由规范化登录态路径派生的同一会话锁；评论抢不到锁时有界退出。
- 默认关闭时保留现有上传及保活路径行为；不关闭浏览器安全特性。

### 策略与合同

- 版本化种子只读，运行时策略位于独立 output 目录；构造与生成不写盘。
- 整个读—修改—原子替换处于文件锁内；损坏文件不能静默覆盖。
- 每类审定模板上限 20、成功样例上限 30；单个 topic 替换不等于可复用模板，不自动晋升样例。
- 严格字段类型、长度、2–4 选项及宿主确定性渲染；保留主题相关性及审查一票否决。

### 调度与架构

- pipeline 仅异步委托独立、有限时 worker，异常不传播到发布主链路。
- worker 有总时限、单实例保护、可观察日志及到期任务发现；不新增 cron、不自动启用生产。
- 到期只是允许领取，实际执行依赖发布确认、既有 daily job 或授权 CLI tick；没有新增分钟级调度，不能据退避时间承诺分钟级 SLA。
- 依赖方向保持 scripts/pipeline → interaction runner/providers/browser/DAL → settings，不反向导入外层。
- 异步子进程不等于物理资源完全隔离；共享代码、数据库迁移与资源竞争仍需明确测试。
