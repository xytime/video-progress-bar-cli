# 字幕失败恢复闭环

用户已于 2026-10-27 以“继续”确认前一回复提出的恢复方向。本单使用 critical-collaboration 完善该方向的执行边界与验收；不重新申请同一方向的确认。

目标：供应商已经返回结果但局部质量拒绝时主动缩小修复；服务故障持久退避；耗尽预算仍保留成功进度、具体错误与音频旁证，进入可诊断的待修复状态，避免不加区分地立即回队。

依赖：CLI → caption processor → recovery receipt/audio helper/provider → settings；pipeline manager → recovery receipt + PipelineDB → subtitle recovery DAL。DAL 不导入 CLI、processor 或 pipeline manager。

## 行为和预算

- 正常 Codex 每批最多 5 段，继续复用 v5 已通过缓存。首次结构/质量拒绝后整批逐段重译，不拼接拒绝候选。单段至多两次，保留全片 source ID 和真实相邻源文；重组后复核批及全片。
- 每个输入/模型/恢复合同持久保存拆分计划、失败位置、实际请求用量。请求总上限为 `2*ceil(N/有效批量)+2*min(N,10)`，136 段最多 76 次；缓存、冷却和未获锁不扣调用次数。600 秒翻译运行预算跨恢复延续，离线冷却不计。每次请求不超过原 120 秒。重启不重置预算。
- 单段重复质量拒绝后最多取两个不超过 30 秒的局部音频窗口，最多 60 秒音频、120 秒离线诊断运行。只加载现有本地 medium，不下载模型、不调用付费 API；保存媒体/ASR/模型/配方/片段哈希和词时间旁证。诊断不直接修改原 ASR、英文或时间轴，也不自动覆盖金额、年份、否定、实体和方向。
- 服务故障独立记账：网络、配额、超时、不可用最多三轮，前两轮分别至少等待 5、15 分钟，并尊重供应商更长冷却；busy 等待至少 60 秒且不消耗服务故障轮数。24 小时未恢复、认证错误、持续质量拒绝或预算耗尽进入 NEEDS_REPAIR。相同失败不会因重启或点击重试而重置次数。
- WAITING 的任务通过既有准备调度器到期续跑；普通候选、原子领取、恢复控制台、网页和 bot 重试共用门禁。NEEDS_REPAIR 不自动再次调用；明确修复后可凭最后失败回执 SHA 原子释放一次，旧账保留。
- 子进程通过本次 UUID、媒体 SHA、ASR/翻译合同和安全错误链的原子回执交接，父进程核验后才改变恢复状态。通知按持久状态转换去重；无变化不反复通知。

## 边界

- 不改变原金额、完整性、原文时间轴、审查或发布门禁；不将不完整字幕标为成功。
- 保留已验收的 AkTXAcMgO3E 136 段翻译和 44 处人工复核修改；新合同如需迁移，必须保留原快照并逐项复核后再保存新快照。本单不重排该历史任务、不渲染或投稿。
- 不修改 VPN、凭据、模型选择、原生中文字幕保留策略或无关 dirty 工作。未来正常续跑继续遵守既有发布授权、维护、租约、限额与提交证据保护；任何已有或不确定提交禁止自动重传。
- 音频复核是诊断旁证，不能保证识别所有错误或自动修复任意事实冲突。遇到不能可靠判断的内容，应明确指出需修复段和原因。
