# OCR 生产采用范围

2026-10-31，用户明确要求“生产环境上请部署生效”。本次只采用已经完成两组完整长片对照的 BMP/JXA 扫描路径；不合入原生 Objective-C 实验、语义分页、翻译恢复及新调度器。

依赖方向：native_caption_router → caption_vision_transport / caption_scan_runtime → file_utils / stage_events；stage_events 未绑定时不写事件文件。没有数据库、平台或外部服务新增调用。

新扫描默认开启 `native_caption_scan_optimization_enabled`：无损完整 BMP、准确模式、简繁英三种语言、关闭语言纠错、逐帧解码；仅逐字节完全一致的相邻整帧复用成功结果。每帧记录及复用证据仍覆盖完整时间轴。检查点按 300 帧或 30 秒保存，完整前缀、源摘要、扫描器摘要及校验和全部验证。旧完整扫描直接复用；旧有效断点继续走原路径，不迁移、不删除。

完整字幕保留规则、语义核验、置信度、覆盖率、最大空隙、内容审核、平台会话锁、投稿去重及未知结果保护不变。16 GB 主机仍只有原来的一个重计算任务，本次不提高并发，也不发起投稿。

既有真实证据位于 `ocr-long-isolated-ab-20261030-0235/runs`：同一 19,290 帧长片两组冷扫描耗时由 3577.29/3515.65 秒降至 2462.04/2424.15 秒，完整 runs 相同，分别降低 31.18%/31.05%。第三组、人工语义金标、真实翻译恢复和合格成片吞吐仍未完成，不把本次局部采用写成整体验收通过。

部署必须以生产 main 为基线，包含现有未提交文件的精确测试覆盖；原生部署保存重叠文件和一致性数据库备份，验证旧进程的既有回执，关闭新准入，在途自然排空后再停止、采用、恢复并回读。生产长片已有旧断点时，此任务不会中途改用新扫描器。

回滚：通过相同受控部署将开关关闭或撤回本次提交，不重置业务状态；保留新旧扫描目录、ASR、翻译、质检和所有投稿回执。关闭开关会采用原路径，不能删除优化检查点来“清缓存”。全局实验分支仍不视为生产就绪。

交付记录：代码提交、测试回执、推送、部署 journal 的 COMPLETE、实际进程 source_hash 和后续新扫描采用证据分别记录。没有真实新扫描或新成片时，相应指标保持未验证。
