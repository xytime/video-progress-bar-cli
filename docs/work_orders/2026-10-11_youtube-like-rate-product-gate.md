## 一、用户明确修改的三条规则

1. 自动《英语世界短视频》：每天运行的第一个视频挂载商品，当天后续视频无需挂载；本类型不使用10%点赞率判断。
2. 除英语世界短视频以外，来自 YouTube 候选并加工的视频：源视频点赞率达到10%才挂载，否则无需挂载。点赞率 = like_count / view_count × 100%，恰好10%算达到。华尔街、TED、AI和其他类型均适用。
3. 后台“添加视频链接／手动添加视频到队列”入口新增“绑定商品”下拉菜单，手动触发抓取任务时可指定商品，默认“不绑定商品”。必须保存到任务并传至实际发布器，不能只增加控件。

只调整视频号商品挂载。内容审核、评分、去重、既有 TED 来源筛选门槛、授权及平台提交保护继续遵循原流程。旧“每条视频必须有商品”的要求，在本次明确无需挂载的情形下被替代。

## 二、补充业务口径：本次完整任务采用

用户于2026-10-11明确要求“请你启动 agent 来开发‘交给 F 的完整开发任务’”，本次按完整任务的已提出建议口径实施；下列口径作为本次开发与验收标准。

- 每日时区为 Asia/Shanghai，按自然日00:00至次日00:00。
- 将当天首个开始正式制作的自动英语世界任务记为“首条”。候选浏览、来源预检、无效链接和单纯抓取元数据不占名额；进入正式制作时登记唯一任务身份及所属业务日。
- 首条失败、等待或重试仍归同一任务，不把后续任务自动变成首条。跨日重试沿用原业务日；次日新任务另计，发布时仍需遵守平台实际限制。
- 手动指定优先于自动规则：选商品即绑定所选商品，默认“不绑定商品”即明确不挂，不再被10%规则或全局默认商品补上。这样的手动任务不占自动英语世界每日首条名额。
- 手动指定低于10%的视频挂商品是明确的人工例外；需在界面说明“手动选择将覆盖自动挂载规则”。用户后续调整口径时，同步修改本节和对应测试。

同一天必须原子选中一个稳定的正式制作任务，重试不得重复占名额。不要改为“每天首个发布成功”，也不要为凑每日一条而重传历史视频。

## 三、统一决策与持久化

采用一套共享决策，生产、预览、通用发布及英语世界独立发布共同使用。区分“是否挂载”与“挂哪件商品”。推荐表达三个明确意图：AUTO、NONE、PRODUCT；具体字段名遵循项目结构。

| 任务意图及类型 | 挂载决策 | 选品来源 |
| --- | --- | --- |
| 手动明确不绑定 | 跳过商品 | 不补默认商品 |
| 手动指定商品 | 要求指定商品 | 该任务保存的精确商品身份 |
| 自动英语世界当天首条 | 要求商品 | 现有英语世界配置、备选及默认 |
| 自动英语世界后续 | 跳过商品 | 不调用选择器 |
| 其他自动 YouTube 视频，有效点赞率>=10% | 要求商品 | 现有类型配置、备选及默认 |
| 其他自动 YouTube 视频，点赞率<10%或指标未知 | 跳过商品 | 不调用选择器 |

- 缺失、非数字、非有限数、负值、0播放或点赞数大于播放数，都不能证实达标；不挂并记录 METRICS_UNKNOWN / INVALID 和原值，不能伪造0%。无YouTube来源不虚构指标。本次不引入新的指标抓取服务。
- 用源 YouTube 指标，分片继承源指标和 youtube_id；自动英语世界名额必须绑定一个实际成片任务，不能给同源的所有分片都挂商品。
- 阈值比较使用未四舍五入的原始比例，显示值不能作为判断依据。
- 首条记录持久化，经 DAL 在事务中登记；至少以发布账号、平台、类型、业务日作为唯一范围。并发运行、服务重启不能选中两个首条；相同任务重入返回原决定。禁止依赖进程内计数或页面顺序。
- 迁移要区分旧任务尚未设置意图（AUTO）与新手动任务明确 NONE，不能把全部历史 source=MANUAL 任务改成不挂。检查所有旧客户端/API调用，明确默认行为与兼容范围。
- 把任务商品意图传过数据库、清单/交付包、子任务、发布命令及实际选择器。类型使用可靠 content_type=ENGLISH_WORLD_SHORT，不能只靠标题猜测。
- 本次发布尝试冻结任务身份、业务日、首条记录、商品意图、策略版本和指标快照。已上传、受理、审核中、已发布或提交结果不明的任务不能因规则改变重传或改挂。
- 明确跳过的任务，必须阻止旧 enable_wechat_product_link 或 --require-product 重新强制挂载，并核实发布表单没有残留旧商品；未知决策不能默认为跳过。
- 自动需要挂载时沿用现有备选及默认链；手动指定的商品失效，不得悄悄换成另一件，进入明确的等待/错误状态。
- 要求挂载的任务仍需确认真实ID与完整名称。库存、商品额度或绑定核验失败按既有机制等待；不允许失败后降级为无商品并提交。

## 四、后台手动入口

在现有“内容类型”附近增加“绑定商品”，首项固定“不绑定商品（默认）”。提供搜索，长名称可查看完整书名、所属店铺及商品ID，沿用已有商品选择器的交互与主题，不新增重型依赖。

清单复用商品设置的商品库/目录来源，包含当前可靠来源中全部上架商品，不能仅列类型配置选中的几本。未核实、停售或无可用身份的条目说明原因并禁止选择；当前只有快照时展示采集时间和完整性，不能宣称实时全量同步。不能为了这个入口捏造平台API或商品ID。

- 加载中禁用商品选择，默认不绑定仍可正常提交；加载失败提供重试和清晰提示，保留URL与裁剪输入。
- 提交商品稳定身份和意图，服务端再次校验所属发布账号、商品身份及允许选择状态；不信任客户端书名或“已核实”标记。
- 无效商品在入队前返回明确错误，不偷偷变为不绑定、不触发抓取；允许不绑定的任务不依赖商品清单成功加载。
- 同次“验证并加入队列”保存URL、裁剪、内容类型和商品意图，避免入队后才补写商品造成竞态。
- 提交期间阻止双击和选择变更；成功后重置为不绑定，失败保留选择供纠正。
- 重复链接继续返回现有状态，不静默覆盖旧任务商品或重启已受理作品。
- 队列/任务详情可回读“自动规则／不绑定／指定商品”、实际商品身份及本次决策原因。保存选择不能显示成已经挂载成功。
- 若任务生成多个成片，单独说明手动意图的继承范围并测试；不能因分片丢失用户明确不绑定或指定商品的选择。

1. 英语世界首条即使点赞率<10%也要求商品；第二条即使>10%仍跳过。次日重新产生首条。按正式制作登记节点计数。
2. 并发启动、服务重启、同任务重复执行、首条失败后重试、跨日重试、候选预检失败、同源多个成片，均不重复占名额或挂到错误任务。

4. 新手动任务默认不绑定，高点赞率或英语世界类型不自动补挂；手选低点赞率任务和当天后续任务按人工指定优先级执行。选择与NONE均经DB/清单/进程完整传递。

6. 跳过任务不调用商品选择器、不被商品专属额度卡住，仍执行原发布门禁并校验无残留绑定。要求商品的任务无可靠绑定不得提交；实际商品ID/全名不一致必须阻断。
