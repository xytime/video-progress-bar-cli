# YouTube 关键词：受控阶段配置转换

Codex · 2026-10-14 · 已批准范围内的运维实现说明；不是生产采用或真实采集证明。

## 阶段交付范围

原生九步部署增加可选的 `OFF → TRIAL → MANUAL → SCHEDULED → ADMISSION` 相邻配置转换；任何开启阶段均可正常恢复 OFF。未传阶段参数时保留原 OFF 部署约束。部署结束时业务持久模式仍为 OFF，准入关闭；只有部署日志 COMPLETE、实际配置回读一致、维护 RUNNING、宿主窗口允许后，才可由正常本机控制面开启试运行。

MANUAL/SCHEDULED/ADMISSION 参数须通过实际数据库作业证据核验，不能把字符串作业 ID 当作真实试运行验收。采集与刷新在保存结果的同一事务中保存不可覆盖的评分快照；缺失的历史记录不回填。计划阶段读取成功作业、项目预算、详情结果、统一评分并保存证据；baseline/freeze/adopt 再次读取并与计划精确比较，漂移拒绝。首轮有效定时规则最多一条，启用、恢复、自动调用和准入共用限制。

MANUAL 需要本轮 TRIAL 配置采用后的成功手动作业、实际搜索及详情预算、至少一个可复算的评分结果；后续阶段沿用同一试运行 ID 链。ADMISSION 额外需要 SCHEDULED 配置采用后的成功定时搜索和刷新；同一候选统计时间必须至少相隔四小时。评分结果可以低于准入线，但实际自动准入仍必须另过现有热度、75 分、内容与累计最多一条限制。无结果、无统计或没有真实自然刷新时保持等待，不补造证据。

## 依赖与保留边界

`scripts/deployment_control → deployment_host → core/keyword_rollout → config/keyword_rollout`。配置模块只依赖标准库；settings 负责载入非秘密字段，core 不反向导入 scripts。保护字段快照由配置层定义，避免维护与阶段适配器相互依赖。

原生 baseline/freeze/stop/backup/adopt/start/resume/restore/verify 全部保留。来源、未知进程、内核锁、排空、正常停止、数据库备份、源码清单、发布保护与调度恢复检查未删除。维护检查接受已绑定阶段配置的前提是实际文件、计划、事务日志、保护快照一致，且业务持久模式 OFF、准入关闭、无在途账本；缺失来源证明仍拒绝恢复。

## 非秘密配置

默认文件是生产 `output/keyword-rollout.json`，由原生 adopt 步骤原子写入。只包含固定阶段配置、非秘密证据、部署 ID 和私有部署目录；不读取、比较或改写 `YOUTUBE_DATA_API_KEY`，不修改 `.env` 或 launchd 凭据。

- settings 启动时只载入允许的关键词字段，格式错误关闭所有关键词能力并保留错误状态。
- 每次真实调用前重新检查文件、有效配置、计划和部署日志；文件缺失、漂移或部署未 COMPLETE 时拒绝搜索。
- UI 状态接口回读白名单配置和配置身份；维护启动须与操作者进程实际配置完全相同。
- 转换前配置保存到私有部署目录 `keyword-profile-before.json`；不改写旧计划或旧回执。
- 计划最多有效 30 分钟，配额观察最多有效 1 小时，未来时间拒绝。采用前再次核验；过期重新核实并编制计划，不修改时间戳。
- TRIAL 固定搜索 3、详情 6、定时与准入 false、累计准入上限 1；真实调用仍受跨日不重置的累计 3/6 限额约束。

## 执行顺序

1. 将协议及预算实现连同最新生产并行改动做最终整合隔离验收。使用原 OFF 协议先部署实现并重启，核实新进程、源码及新状态字段。旧 CLI 在首次采用期间运行已加载的旧协议，不能拿旧计划重放新阶段转换。
2. 现场重新核实维护状态、宿主保护窗口、实际 Cloud 配额、项目与本机共享调用者；准备非秘密证据 JSON。用户本机比对与无外部共享声明已经取得，无需再索取密钥。
3. 用新 CLI 编制带 `--keyword-stage TRIAL --keyword-evidence <非秘密证据文件>` 的新计划；其他 target/tested-manifest/overlay 参数仍按原协议必填。阶段配置转换与源码采用一并受项目部署锁约束。
4. 执行原生九步。维护中和部署完成前不开放持久模式。任何未知来源、漂移或步骤失败立即保持当前现场；按 `status` 和 `recover` 核实，不手工改日志、删锁、强杀或恢复调度。
5. COMPLETE 后现场重新验证窗口及配额，通过正常会话启用试运行，最多累计三次真实搜索。核对请求预算、结果入库、去重、评分及正常 OFF 恢复；无结果或不达标如实记录。
6. 试运行证据完整后依次编制 MANUAL、SCHEDULED 新计划；启用最多一条规则后等待自然采集与至少四小时的真实统计刷新，再核验 ADMISSION。各次阶段采用期间持久模式仍 OFF，采用后再经正常控制面开放。完整记录实际结果，不把 OFF 部署或阶段配置采用当作总目标完成。

## 故障处理

启动超时但配置已采用：业务维护状态不自动恢复，阶段配置的 COMPLETE 校验继续阻止搜索。待原生进程、锁及网页回读能证明启动完成后，原生 `recover` 才能确认该步；未知结果不会盲目重试。配置写入前失败或部分源码采用仍遵循原部署器的 UNKNOWN 停止规则，须现场核实后制定恢复动作，禁止伪造成功回执。

正常关闭：先经控制面关闭持久搜索和准入并等待已领取任务结束，再新建目标 OFF 的计划执行同一九步。关闭阶段不清除累计预算，不删除搜索历史；最终以累计账本未增加证明部署期间无搜索，避免项目字段清空后日用量归零掩盖请求。
