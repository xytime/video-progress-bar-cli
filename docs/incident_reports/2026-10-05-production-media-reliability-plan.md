## 已确认缺陷与尚待验证的假设

1. 下载策略对首选失败统一降级 curl，没有区分身份验证、限流、传输故障和损坏产物；不能据此期待同一身份下更换下载器恢复。
2. 下载开始与降级前会校验分片，但最后失败后可能留下 0 字节轨道；错误消息包含大量进度输出，核心故障不易识别。
3. Google 兜底直接调用第三方逐段批量方法，无主动节流；单次异常返回整批空串，丢弃已完成结果。候选成功日志在验证返回值前输出。
4. 各供应商独立预算默认 300 秒，外层翻译看门狗为 720 秒；缺少贯穿供应商切换、重试与质量检查的共享预算。当前模型池还记录了 Gemini 剩余请求时限小于 API 最低时限的错误，以及 DeepSeek 402。
5. yt-dlp 为 2026.08.19，与调查时官方 latest 一致；本机未安装 yt-dlp-ejs，但已有 `--remote-components ejs:github`。不能仅凭缺包断言挑战解算失败；需核对运行时与实际解算回执。
6. 下载日志反复记录 Clash 节点读取/切换 HTTP 404；实际请求出口和对下载的影响尚未证实，不能据此自动切换整机网络。

## 推荐实现范围

### 下载

- 统一下载健康预检：yt-dlp、兼容 EJS、JS runtime、实际代理路径与媒体工具；需要依赖修复时仅安装与当前 yt-dlp 匹配的官方 EJS 包。
- 根据真实失败证据修复下载路径；身份验证拦截和限流进入可解释的有界冷却，普通传输故障才有限降级。
- 保留通过验证的音视频轨和可续传状态；只隔离确认无效的目标文件，不删除未知缓存。
- 成片必须通过真实音视频双轨、正时长与容器验证。下载失败、取消和超时均收敛进程组、记录核心原因，避免失控重试。
- 代理 404 修复限于项目实际需要的 API/选择器适配，不擅自改整机代理或出口；若恢复必须选择新出口，再确认该部分。

### 字幕

- 让供应商切换、请求、重试、节流及质量检查共享整片预算，避免内外超时冲突；不足 API 最低请求时限时停止该请求，不提交必败请求。
- Google 逐请求节流、有界退避，保留已完成段落；失败明确记录段号、供应商与原因。
- 按现有供应商配置执行，不引入新的付费服务。修正 402、地域限制和限流的故障分类与冷却。
- 成功日志只在实际完整返回且验证后记录；翻译完整覆盖与对齐、数字事实及内容审查闸门继续生效。缺失段落不得渲染或发布。

### 运行采用与具名恢复

- 保护现有 `topic_clues` 无关未提交工作。按项目 main 纪律，仅提交与推送本次修复文件。
- 隔离测试通过、目标差异确认且运行空闲后，更新实际采用修复的 worker，并从新心跳/日志验证版本与配置。
- 恢复前再次核对上述四条的账本和文件证据；只有仍然未提交、未命中政策拒绝的目标可恢复，不批量重置 FAILED，不清除历史投稿证据或重试计数。
- 对上述目标具名执行正常审查、制作和发布流程，提交一次后即按原生 ID 只读核验；结果不确定时停止重传。
- 较早已受理作品只读对账；抖音熔断和选择器校准不在本次实现范围。
