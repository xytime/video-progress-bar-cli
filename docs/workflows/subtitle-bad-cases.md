# 字幕 bad-case 记忆与每周回测

2026-10-27 用户确认：先针对具体错误有效修复，普通相同重试不能代替修复；剩余少量问题（含金额量级错误）可按整片阈值告警继续，Telegram 提醒并保存原始案例。大量问题和结构错误仍停止。

案例库是应用运行数据，不是 Codex 个人记忆。`subtitle_bad_cases.save_bad_case(root, payload)` 保存完整 JSON，返回 `case_id/path/sha256`，文件位于 `root/cases/<ID 前两位>/<ID>.json`。保存先落盘再原子创建，不覆盖已有案例；同一内容重复保存幂等，读取核验文件 SHA、内容 ID、文件名并拒绝符号链接。损坏案例会使回放报错，不能悄悄从统计中消失。

每条原始快照默认 `review.status=unreviewed, ground_truth=false`。`payload` 保存原文和译文、时间、主机问题证据、实际修复历史，以及候选/媒体/ASR/合同/策略摘要。检测器发出的 `NUMBER_MAGNITUDE_MISMATCH` 等旗标只是待核实证据；它们不能自行充当人工真值。复盘、修复和人工标签均不得覆盖原始快照。

离线回放入口：

```bash
PYTHONPATH=src .venv/bin/python scripts/subtitle_bad_case_backtest.py \
  --store /绝对路径/到/字幕bad-case库 \
  --output /绝对路径/到/本周新目录/report.json
```

不提供 `--store` 时只运行冻结回归集。脚本不请求模型、不下载音频、不修改字幕或任务、不发布。它直接调用生产的整片容错策略，并给出旧严格事实门的同输入对照。冻结集包含独立的 `regression` 与 `holdout` 标记、上下文误拦反例、残余金额/方向问题、结构硬门、段数/比例/并集时长超限、反复相同表达、未修复及简单重复调用。

报告同时保留两组数字：

- 固定样本的策略一致率、正确样本误拦率、未经授权的错误放行率、按批准规则容忍的稀疏问题比例，以及旧门拦下的稀疏案例数。这是主机规则回放，不能称为翻译准确率或模型修复率。
- 独立人工标签支持的真实修复率、误拦率、错误输出被接受比例、其中告警容忍数与无告警错误放行率。没有标签或没有有效修复执行证据时分母为零，对应指标为 `unknown`，不能输出 0% 或宣称提升。

人工确认后可新增一个独立标签文件，不能自动把检测结果转成这些标签：

```json
{
  "schema_version": "subtitle-bad-case-labels-v1",
  "source": "human",
  "reviewer": "实际复核者",
  "reviewed_at": "2026-10-27T12:00:00+08:00",
  "cases": {
    "完整case_id": {"input_has_error": true, "output_has_error": false}
  }
}
```

带 `--labels /新标签.json` 回放即可统计人工真值。`input_has_error` 指修复前候选，`output_has_error` 指快照中最后实际候选。只有输入有错、输出经过有效修复且两端经人工确认的案例进入修复率分母；金额疑点经人工确认为误报应标为输出无错。标签会进入语料摘要，来源不明或错误布尔值会被拒绝。

每周复盘应聚合新案例的错误类型、受影响段数/时长、修复策略及真实调用量，提出有依据的小范围修正规则或提示词，再用同一冻结语料和人工标签回测。使用 `--compare /上一版/report.json` 比较；语料或标签变化时会明确显示不可比较，不能拿不同样本的百分比作改善结论。扩大语料时保留旧报告和旧语料，以便固定集前后对照。

只有修复率改善且正确反例误拦与未经授权放行没有退化，才可以据此推进对应实现；缺人工真值时只报告策略回归证据和待复核样本，不宣称语义质量提升。不得通过放宽已批准阈值、删掉失败样本或改变结构硬门来制造“提升”。每周任务应引用具体报告、版本与样本量，保留无法判定的限制；没有新案例也保留一次固定集回测记录。
