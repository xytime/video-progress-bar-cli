# 原片中文字幕处理流程

制定日期：2026-10-27。依据：用户明确要求“这个视频原本就有中文字幕，所以我们没有必要再叠加”，并要求可行后制定进流程。

## 正式规则

**先检查原片字幕，再决定是否生成字幕。已有完整、清晰且与对白对应的中文字幕，优先保留，不重复叠加。** 简体、繁体、纯中文字幕及中英双语字幕均适用。

本规则适用于普通转载处理流程。英语世界、配音改写等已有专门制作规格的任务，按其明确规格执行；不能用本规则跳过该任务明确要求的教学、配音或字幕校验。

## 处理顺序

1. 下载并验证源片，记录视频标识与源文件 SHA-256。先检查原片可见字幕和已有确认记录，再进入字幕生成或原字幕修复。
2. 按下表分流。识别结果必须针对实际源文件，不能仅凭标题、视频简介、字幕轨列表或一张截图判定整片。
3. 内容审核仍需覆盖整段内容。优先复用同一源片已验证的 ASR、译文或字幕文本；缺少审核正文时补齐文本。用于审核的转写、翻译不等于需要生成或烧录新字幕。
4. 保留原字幕的任务跳过重复字幕生成、烧录及为替换字幕而进行的遮挡、擦除、画面修复。交付版本不得又被旧的加字幕版本或额外画面叠层替换。
5. 原片满足交付格式时原样交付，验证交付文件与源文件摘要一致。如必须转码或调整画幅，另行验证字幕完整可见、未被裁切、遮盖或重叠；不得把字节一致凭证用于转码成片。
6. 文案、正常封面、内容审核、发布授权、会话锁、重复投稿保护及平台回执要求照常执行。

| 源片情况 | 处理决定 |
| --- | --- |
| 已确认完整、清晰的中文字幕，包含繁体或中英双语 | 保留原字幕，不重复叠加 |
| 确认没有中文字幕，或只有英文字幕 | 进入原有中文字幕制作流程；原有英文字幕仍按对应布局规则处理 |
| 只有中文标题、姓名牌、幻灯片或零星中文 | 不能据此判定已有完整中文字幕，继续检查对白对应字幕 |
| 中文字幕仅覆盖部分对白、明显错译、难以辨认，或识别证据不足 | 复核缺失时段及问题，形成局部处理决定；不能默认整片再叠一套，也不能默认跳过字幕 |
| 仅有可选软字幕轨，普通播放器画面未显示 | 不视为已烧录中文字幕；按实际交付播放条件判断 |

## 确认证据与恢复

- 检查覆盖有对白的各时段及字幕切换；片头片尾、无对白间隔不要求出现字幕。抽样可辅助初筛，不能单凭少量抽帧宣称整片覆盖。
- 记录确认者或识别方式、源文件摘要、字幕语言、覆盖与可读性结论、审核正文来源。人工确认不能伪装成自动识别结论。
- 源文件改变后，原有确认不能直接复用；文件名或 YouTube ID 相同不代表内容相同。
- 判断不清时保留下载、ASR、译文及 OCR 检查点，复核具体不确定项，避免从下载开始整条重跑。
- 新规则不触发历史视频重制、重发或状态重置。`UNCERTAIN`、已提交、审核中及已发布记录继续按原发布证据处理。

## 当前实现与自动化边界

截至 2026-10-27，已实现并验证的是**按源文件摘要绑定的单片人工确认保留路径**：`config/native_caption_sources.json`、`native_caption_source.py` 及流水线对应分支。`5Fi-oCg2WxQ` 已使用此路径，交付文件与源片摘要一致；相关隔离测试 32 项通过。本次制定规则仅更新流程文档与代理执行约束，不新增通用自动识别或改变运行服务。

现有 OCR 用于原字幕位置与修复校验，不能可靠证明中文字幕覆盖完整对白。不得把“检测到中文”直接改成跳过字幕的全局开关；未有确认记录的视频，目前仍不会由程序自动采用保留路径。

通用自动分流开发应遵循以下验收要求：

- 在重复字幕渲染之前给出“保留 / 生成 / 复核”决定，明确证据和不确定项；不能把 OCR 异常当成没有中文字幕。
- 完整简体、繁体、双语字幕进入保留路径；英文字幕、中文标题与幻灯片不误判；部分覆盖与低清字幕进入复核。
- 源片摘要、单片决定及审核文本绑定；新增另一视频的确认不能使旧视频凭证失效。当前凭证绑定整个确认清单，扩大清单前须解决这一限制。
- 保留路径不产生重复字幕，内容审核及发布检查仍执行；字幕相关步骤不要求伪造 ASS 文件。
- 验证有效缓存复用、源片变更失效，以及历史已提交记录不被重发。

上述自动分流属于后续实现范围；不能把本流程文档已生效表述成通用检测已上线。
