# 原片中文字幕处理流程

制定日期：2026-10-27。依据：用户明确要求“这个视频原本就有中文字幕，所以我们没有必要再叠加”，并要求可行后制定进流程。

## 正式规则

**先检查原片字幕，再决定是否生成字幕。已有完整、清晰且与对白对应的中文字幕，优先保留，不重复叠加。** 简体、繁体、纯中文字幕及中英双语字幕均适用。

本规则适用于普通转载处理流程。英语世界、配音改写等已有专门制作规格的任务，按其明确规格执行；不能用本规则跳过该任务明确要求的教学、配音或字幕校验。

## 处理顺序

1. 下载并验证源片，记录视频标识与源文件 SHA-256。先检查原片可见字幕和已有确认记录，再进入字幕生成或原字幕修复。
2. 按下表分流。识别结果必须针对实际源文件，不能仅凭标题、视频简介、字幕轨列表或一张截图判定整片。
3. 内容审核仍需覆盖整段内容。优先复用同一源片已验证的 ASR、译文或字幕文本；缺少审核正文时补齐文本。用于审核的转写、翻译不等于需要生成或烧录新字幕。
4. 保留原字幕的任务跳过重复字幕生成、烧录及为替换字幕而进行的遮挡、擦除、画面修复。交付版本不得又被旧的加字幕版本或额外画面叠层替换。
5. 原片满足交付格式时原样交付，验证交付文件与源文件摘要一致。如必须转码或调整画幅，另行验证字幕完整可见、未被裁切、遮盖或重叠；不得把字节一致凭证用于转码成片。
6. 文案、正常封面、内容审核、发布授权、会话锁、重复投稿保护及平台回执要求照常执行。

| 源片情况 | 处理决定 |
| --- | --- |
| 已确认完整、清晰的中文字幕，包含繁体或中英双语 | 保留原字幕，不重复叠加 |
| 确认没有中文字幕，或只有英文字幕 | 进入原有中文字幕制作流程；原有英文字幕仍按对应布局规则处理 |
| 只有中文标题、姓名牌、幻灯片或零星中文 | 不能据此判定已有完整中文字幕，继续检查对白对应字幕 |
| 中文字幕仅覆盖部分对白、明显错译、难以辨认，或识别证据不足 | 复核缺失时段及问题，形成局部处理决定；不能默认整片再叠一套，也不能默认跳过字幕 |
| 仅有可选软字幕轨，普通播放器画面未显示 | 不视为已烧录中文字幕；按实际交付播放条件判断 |

## 确认证据与恢复

- 检查覆盖有对白的各时段及字幕切换；片头片尾、无对白间隔不要求出现字幕。抽样可辅助初筛，不能单凭少量抽帧宣称整片覆盖。
- 记录确认者或识别方式、源文件摘要、字幕语言、覆盖与可读性结论、审核正文来源。人工确认不能伪装成自动识别结论。
- 源文件改变后，原有确认不能直接复用；文件名或 YouTube ID 相同不代表内容相同。
- 判断不清时保留下载、ASR、译文及 OCR 检查点，复核具体不确定项，避免从下载开始整条重跑。
- 新规则不触发历史视频重制、重发或状态重置。`UNCERTAIN`、已提交、审核中及已发布记录继续按原发布证据处理。

## 当前实现与自动化边界

2026-10-27 用户要求“继续完成任务”后，实现了普通流水线的自动分流。流水线调用 `auto-caption --preserve-source-chinese`，在 ASR 检查点之后、翻译/ASS/字幕修复之前执行。独立 CLI 默认不启用；已指定配音的任务不接入此自动保留路径。

- 本机 Vision 按实际帧率解码扫描每一帧，识别简体、繁体和英文；检查完整解码、恒定帧率及零起点等时间轴条件。源片与识别器摘要绑定扫描缓存。
- 使用项目现有 Codex 文字/图像结构化入口核验每段对白及实际字幕画面，不新增付费 API 回退。完整中文字幕必须同时通过语义正确性、逐种文字的画面可读性复核及宿主覆盖校验；“检测到中文”不能直接放行。
- 每段有对白的区间，中文字幕帧覆盖至少 95%，连续空隙不超过 250ms；OCR 最低分数 0.5，且必须有实际画面核对。阈值是本版保守边界，不是普遍识别准确率保证；不通过进入复核，不自动降低阈值。
- 每批最多 6 段、24 张图，按实际字幕变体动态缩小批次；不再使用整片 144 段、72 批及 15 分钟的固定上限。扫描预算按实际帧数增长（至少 20 分钟），父任务预算同时考虑帧数和语义批次；单次 OCR 与服务请求仍有超时。超时、认证失败、解析异常或证据不足均为复核，不当作没有中文字幕。
- 2026-10-28 修复：扫描每 30 秒视频帧进度及异常退出时原子保存断点。后续获授权执行时，核对源摘要、扫描代码摘要、视频参数及断点完整性后续扫；先顺序解码跳过已核验帧，避免随机定位漏帧。旧版无完整性校验的部分扫描文件不直接复用，已有有效 ASR 和正式字幕决定不重置；没有新增自动重试。
- Vision 坐标为有限、顺序正确且与画面有实际交集时裁到画面范围，保留原始框、调整帧号和原置信度；框无可见面积、倒置或非有限值仍阻断。几何规范化不等于字幕完整或可信，原有低置信度与对白覆盖审查继续执行。
- 低置信度疑似汉字也附上对应实拍帧，审查者可凭可见衣物、图案或英文字母排除 OCR 假阳性；不能仅按低分丢弃。首中尾画面、完整扫描覆盖、全部中文 runs 及非中文示例共同提供审查依据。逐帧坐标修正审计保留本地，不重复塞入语义提示词。
- 自动决定保存在 `*_vertical.source-captions.json`，完整 OCR/语义证据保存在对应的 `.source-captions.evidence.json`；`PRESERVE` 的交付凭证为 `.native-captions.json`。凭证绑定单片决定、审核正文、实际源文件与交付摘要。裁剪源路径在提交阶段仍保持一致。
- 自动保留目前适用于可原样交付的竖片。横片已有中文字幕时进入复核，待确定不裁字幕的竖版布局；不将横片复制后冒称竖版。
- 复核使用现有失败详情呈现，带 `[NativeCaptionReview]` 原因，保留 ASR 和有效扫描缓存。没有新增审核队列或自动投稿重试。已准备完成的历史成片不会仅因新增规则而重制。

人工确认路径继续保留，优先于自动检测。`5Fi-oCg2WxQ` 仍使用原有确认与原样交付凭证。旧版凭证借助只读快照 `config/native_caption_sources_legacy_v1.json` 兼容校验；不改写已提交证据。新增人工条目或自动决定不使其他视频凭证失效。

验收要求：

- 在重复字幕渲染之前给出“保留 / 生成 / 复核”决定，明确证据和不确定项；不能把 OCR 异常当成没有中文字幕。
- 完整简体、繁体、双语字幕进入保留路径；英文字幕、中文标题与幻灯片不误判；部分覆盖与低清字幕进入复核。
- 源片摘要、单片决定及审核文本绑定；新增另一视频的确认不能使旧视频凭证失效。
- 保留路径不产生重复字幕，内容审核及发布检查仍执行；字幕相关步骤不要求伪造 ASS 文件。
- 验证有效缓存复用、源片变更失效，以及历史已提交记录不被重发。

## 2026-10-29 扫描提速候选（默认关闭）

`native_caption_scan_optimization_enabled=false` 保留既有识别设置。启用候选时仍按原分辨率、
原帧率完整解码每一帧，仅当相邻完整 BGR 图像的形状、类型与全部像素逐字节相等，才引用
前一实际成功 OCR 的结果；不是抽帧、相似图判断或固定字幕区域扫描。空 rows 也须来自成功
OCR，失败帧不推进完成边界。每次恢复的第一帧重新识别，不凭已有像素摘要推断相等。

- 新 native 扫描位于源摘要目录的 `native-scan-v3-exact/`，证据增加 `frame_evidence`，
  记录完整解码帧数、复用区间、实际识别帧号和完整像素摘要。原有 v2 完整缓存继续按原合同
  验证，已有合法 v2 断点继续原引擎，不因开启优化丢弃数小时扫描。新 v3 断点保存最多300帧
  的原子块及校验 manifest，恢复重放 native 的已校验每帧结果重建 runs，结束时才写完整扫描。
- 原位修补的 OCR 与 native 分流保持两个合同：前者整幅文字与人脸定位，后者简繁中英
  识别加逐段语义审查。修补器仅在独立 `scan-v2-exact/` 命名空间保存有完整性校验的
  observations 块，每块最多300帧；只有 manifest 已提交的连续前缀可恢复。
  预加工调度上下文中即使优化关闭，也使用独立 `scan-v2-checkpoint/` 分块恢复，仍每帧实际识别
  且保留默认 PNG；不会偷偷启用像素复用。两者都不共用另一 OCR 合同。
  修补后的残字复核仍重新 OCR，不引用原片识别结果。
- 优化或预加工上下文内，墙钟30秒或300个完成帧保存断点；原子保存成功后才允许调度器让行。
  默认关闭且不在预加工上下文时保留旧 v2 cadence。旧 v2 在预加工上下文续扫仍写完整快照，
  不能宣称它已有 v3 的分块写盘收益，须单独比较 checkpoint_seconds。
  让行是等待态，不是质量失败、没有中文字幕或自动发布许可。
  native 的扫描硬预算随断点保存已耗墙钟，重领扣除；旧无该字段的历史断点仅首次兼容。
  原位修补保存累计扫描墙钟供证据，仍沿用单帧60秒超时，没有新增整片硬截止。
- `caption_scan_png_compression` 仅在优化候选中指定无损 PNG 压缩等级（0–9），不改变像素、
  OCR 语言、识别等级、置信度或覆盖阈值。没有生产双 worker 开关。
- `[CaptionScanMetrics]` 与阶段证据区分 native、原位修补、语义审查，记录真实 OCR 次数、
  同像素复用、缓存/断点命中、解码、编码、Vision往返、规范化及断点耗时。指标不带字幕正文。

启用验收先固定本次 Yux/vD/DWb/VN5/uWq/GLmf 慢任务样本，补人工标注的完整简体、繁体、
双语、部分中文、无中文、小字与移动字幕。固定源摘要、ASR、原分辨率/帧率和识别参数，
在隔离输出中交错 A/B，每项至少3次；分别报告冷扫描、有效缓存、恢复及语义审查耗时。
“冷”指应用扫描缓存未命中，不清理生产或系统缓存。固定真实样本集冷扫描中位耗时下降20%
是启用门槛而非收益承诺，单样本超过5%的退化需解决；完整长片还须证明峰值RSS受预算约束、
不持续新增swap，全部帧可追溯且质量回归无放宽。未通过保持默认关闭。

回滚关闭开关并恢复旧引擎；不得覆盖或迁移原 v2 缓存、历史决定与已提交凭证，也不能移除
识别器摘要校验来命中缓存。新证据保留用于复核，历史 `UNCERTAIN` 不被重发。

代码、真实样本与部署采用证据分开记录；不能把测试通过表述成所有视频都能自动识别成功。

`scripts/benchmark_caption_scan.py` 仅接受显式源与 EXT2T 全新验收根，默认只导出最多0.5秒
的原分辨率/帧率 FFV1 小样，并逐帧回读确认像素一致。`--run-ocr` 才执行单 worker 三轮
AB/BA/AB，每轮冷应用缓存，系统缓存不清理；`--probe-only` 限单源一对用于沙盒兼容探针。
合成 gold 只报告已知文字/出现帧，不代表 ASR 对齐或语义审核。无论微样本收益如何，
工具都会标记完整长片启用门槛未通过。保留独立源码摘要、完整 runs、分项指标与资源收据。
合成字体逐字验证，TTC 默认子字体缺字时拒绝生成 gold，不能把空字形当作 OCR 漏识。
`scripts/verify_native_scan_cache.py` 只读选定源并复制已有 v2 full/partial，开启优化后要求
完整缓存命中、零 OCR、禁 JXA/网络且副本未改写；它不能证明实际 partial 续扫或字幕语义。
