⚡ 修正后结论
会话失效 不是 cookie 过期（有效期 ≈400 天），不是 keepalive 失灵（已启用且每小时刷新成功）， 也不是走了境外代理——微信确实直连，出口是 中国北京联通住宅 IP（123.119.162.223），对国内平台是「好 IP」。 真因已坐实（2026-06-25 判定实验结论）：
✓ 候选②：微信服务端会话硬上限（~24h）——实验当天出口 IP 整天未变，会话仍在 ~24h 准时失效， 与 IP/cookie 无关，keepalive 每小时刷新也无法延长其绝对寿命。属平台策略，技术上无法绕过，必须人工重扫。
✗ 候选①：住宅动态 IP 轮换——已推翻（IP 全程不变却仍失效，证明失效与 IP 变化无因果）。

1. 现象

  • 扫码登录后发布正常；约一天后转 LOGIN_REQUIRED，必须人工重扫。
  • 今日(6-24)：02:25 / 02:40 两条高分视频卡 LOGIN_REQUIRED；重扫后立即发布成功 → 除登录态外链路健康。
  • 15:05 重登后，15:33 keepalive 确认 Session active 并刷新 state——会话正常。
  • 2026-06-25 判定实验结论：出口 IP 整天未变，会话仍在 ~24h 准时失效 → 坐实候选②（服务端 ~24h 硬上限），候选①（动态 IP）排除。

3. 两个候选根因（图解）

候选 ①住宅动态 IP 每日轮换
为何 keepalive 救不了：IP 一变，连 keepalive 自己也从新 IP 发请求，无法"续"回旧绑定。
候选 ②微信服务端会话硬上限
为何 keepalive 救不了：服务端按"绝对登录时长"封顶，滑动刷新不重置计时。

5. 解决方案（按判定结果）

若为 ① 动态 IP —— 让微信出口 IP 固定下来

  • 向联通申请固定公网 IP（家宽/企业宽带可办），从源头消除每日换 IP。最干净。
  • 或：为微信域名（*.weixin.qq.com / *.qq.com）单独走一条固定 IP 的国内住宅代理/SD-WAN，其余流量不变。
  • 注意：当前机场节点只有 TW/US/SG/JP，无大陆节点，故"钉到国内节点"需另购国内固定出口；不能用现有机场节点（境外，对视频号更糟）。

若为 ② 服务端硬上限 —— 网络改不了，只能让重登无痛

  • 微信强制 ~24h 重扫属平台策略，技术上无法绕过（必须人工扫码）。
  • 对策是把重登变成"无感例行"：在预测失效前主动推新二维码、走可靠到达通道、一键扫码。

通用兜底（无论①②都该做 · 代码侧 · 零网络风险 · 可立即实施）

  • 出口 IP 漂移检测：每次发布/keepalive 记录直连 IP，变化即 Telegram 预警「IP 已变，会话可能失效」。
  • 失效前预警：基于历史失效节律，在临近 24h 前主动推送二维码（而非失效后才告警）。
  • 二维码可靠投递：走 Telegram sendPhoto（今日已实测 HTTP 200 可达），附剩余时效与一键重发；不依赖不可见的图床。
  • 失效即自动备好新码：检测到 LOGIN_REQUIRED 立刻生成并推送二维码，把"停摆数小时"压到"几分钟内重扫即恢复"。
